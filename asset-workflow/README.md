# asset-workflow

美術素材流程 Skill：作品的外觀與素材（影片、插畫、遊戲美術、配樂與音效）先和你定下參考基準，
再由 AI 自己對照基準逼近，你只看基準、試作品與成品。只用 Markdown 與 git，不依賴特定工具的指令或 hook。

## 為什麼和 dev-workflow 分開

程式可以先寫測試再實作；美術沒辦法先寫「好不好看」的測試，標準要由你來定，素材又多半是不能合併的大檔。
所以這個 Skill 把「先寫測試」換成「先定基準」：

| | dev-workflow | asset-workflow |
|---|---|---|
| 適用 | 程式行為、工具、生產流程、軟體介面 | 對照參考基準驗收的作品外觀與素材 |
| 順序 | 先寫測試，再實作 | 先定基準，再逼近基準 |
| 審核 | 預設主代理代審（DEV-A、DEV-B） | 美感由你審三關；其中的程式修改仍有 DEV-A、DEV-B |
| 版本 | 分支與合併 | 再加上鎖定清單、帶版本號的成品與成品庫 |

分不清該走哪個時，走 dev-workflow。

## 你會看到的三個審核點

| 審核點 | 你要做的事 |
|---|---|
| ART-0｜基準 | 和 AI 來回確認參考基準（例如十張概念圖、一段實拍影片）和「接近」的衡量方式，並核准這次的計畫與 Git 範圍 |
| ART-1｜試作品 | 看並排圖、量化結果、AI 的主觀評分和沒達標的地方，決定接受、繼續改，或回頭修正基準 |
| ART-2｜成品 | 看過成品後核可；之後才會合併、歸檔與打 tag |

中間的每一輪 AI 自己對照基準，不會請你看圖；每輪的紀錄放在報告裡，你想看隨時可以翻。
量測寫法、遮罩、工具做法這類技術判斷 AI 自己決定，列成「替你做的技術決定」放進 ART-1。中途找你的是：
預算超標、要改作品預設或其他作品、要動範圍外的檔案、受保護的規則、下載與 commit 與發佈這類本來就要逐次同意的事，
以及停止條件、重過 ART-0、需求取捨與缺少證據；審查意見照預設做法仍談不攏時，照 dev-workflow 的不收斂規則處理。

專案有 art bible（1～2 頁加 6～12 張定錨圖）時，每次 ART-0 只確認這次的參考符合它；還沒有時，第一次 ART-0 會一起提出草稿。

## 會守住的事

- 量化指標全部通過不等於核可；量不到的差異（例如浪的形狀、筆觸）會寫進報告，由你決定。
- 開工後改了量測規則，會同時列出原規則和新規則的結果，你確認前不算達標。
- 改了共用的素材或程式，所有用到它的已核可作品都會和核可的版本逐段比對。
- 每一個交付的版本都有能重現它的 tag；tag 只打在合併後、確認能重現的 commit。
- 無法重新產生的檔案（母帶、基準）不放在可刪的輸出資料夾；成品庫與參考庫不會被任何清理碰到。
- 參考影片與圖片不進 repo：放專案宣告的參考庫，repo 只留清單與雜湊。
- 做量測工具前先用小腳本試量，分不出缺陷的指標不做工具，改用並排與評分。

## 檔案

- `SKILL.md`：流程本體（AI 讀）。
- `references/reference-review.md`：art bible、挑基準、試量與量測、每輪對照、ART-1 交件。
- `references/asset-management.md`：檔案的五種狀態、目錄、命名、參考庫、鎖定、交付與發佈。
- `assets/templates/art-bible.md`、`assets/templates/reference-set.json`、`assets/templates/releases.json`：
  art bible、基準清單與成品紀錄的範本。

## 安裝

更新既有安裝前，先刪除已安裝的舊 `asset-workflow` 資料夾再複製；`cp -r`／`Copy-Item`
不會刪除新版已移除的舊檔案。下列以 Claude Code 為例；其他工具複製到各自的 Skill 目錄。
這個 Skill 會用到 dev-workflow 的程序，兩者要一起安裝。

```bash
# macOS / Linux（於框架根目錄執行）
cp -r asset-workflow ~/.claude/skills/
```

```powershell
# Windows（PowerShell），於框架根目錄執行
New-Item -ItemType Directory -Force "$HOME\.claude\skills" | Out-Null
Copy-Item -Recurse -Force asset-workflow "$HOME\.claude\skills\"
```

## 還沒驗證的部分

這套做法目前只在一個影片專案走過一次完整版本。多人同時改同一個二進位檔需要的 LFS 檔案鎖還沒練到；
遊戲專案的匯出與匯入、特定平台的發佈規格也還沒寫進來。
