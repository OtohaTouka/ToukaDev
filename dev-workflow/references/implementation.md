# 實作與驗證程序（步驟 5–9、11）

開始修改或驗證時讀取。實際命令以專案 AGENTS「技術棧與執行命令」為準，本檔不另列命令。

主代理代審模式優先由執行者完成本程序、整合及候選重建，主代理檢查結果並提出修正意見。
寫的人和審的人不能是同一個：主代理自己修改或撰寫的內容交新上下文的 reviewer，不得自己核准；
仍有效的驗證不因換角色而重跑。一般 TDD 預期 RED 不算除錯失控；
第三次同方向相同錯誤依 debug-escalation 接續，保留原 FAIL 與中斷點。

## 步驟5｜寫測試，確認失敗（Red）

先寫針對行為、一次只測一件事的測試並執行，確認因功能尚未實作而失敗；測試意外通過時先確認需求是否已有覆蓋，
不為取得 RED 製造無關失敗，直譯器或依賴啟動失敗不算 RED。
多個條件組合的判定用對照表測試，每種會改變結果的組合一列。
用 mock 取代真實物件時用 spec（或語言的等價做法），不斷言不存在的方法；依賴外部服務的格式限制時，依官方文件的限制寫離線契約測試，不只 mock 成功回應。
會寫檔或測路徑穿越的紅測試在修改前就會真的執行；先確認寫入目標落在沙盒內（例如在沙盒裡放一層誘餌上層目錄），突變一次只拿掉一道防線。

## 步驟6｜實作功能或修復（Green）

只寫讓測試通過的最少程式碼、不提前優化；新常數、型別、設定值加在 SSOT 定義的位置再引用；依已審計畫的 SOLID
判斷實作，設計證據不成立時補正方案，不硬造 class 或繼承，也不把 OCP 解讀為禁止修改既有程式。

## 步驟7｜跑測試，確認通過

執行相關測試與全體回歸測試，全部通過才繼續；有失敗就回步驟6。

## 步驟8｜重構精簡（Refactor）

在測試保護下只合併真正相同的責任、拆分過長函式、讓命名表達意圖，不新增 SSOT 違反，並遵守 AGENTS 依語言與框架
適用的規則；重構後重跑步驟7。

## 步驟9｜靜態檢查與腳本驗證

依專案 AGENTS「技術棧與執行命令」執行全部 lint、守衛與安全檢查，零 ERROR 才繼續；失敗就修復後重跑，不得跳過。
判斷通過看每個檢查的 exit code（取檢查命令本身的，不是接在管線後面的 `tail` 這類命令的）與完整失敗清單，不截斷輸出；跳過的測試數與原因要和基準（同一個環境在基準 commit 跑出的跳過數）比，多出來的跳過一律當失敗，除非已照下一句列為固定例外（例如新增只在某些平台跑的測試）；回報附命令、exit code、輸出最後一行、跳過數、在哪個資料夾與 commit 跑、用哪個直譯器或環境（例如 venv 路徑），以及範圍是全量還是哪些路徑。
只跑部分時寫明範圍、不寫「全過」，全量的檔數或項數和基準比；改了依賴或鎖檔時，全部驗證用候選自己的環境；交件前跑專案宣告的全部檢查，不自挑子集。
環境造成的固定例外要列在計畫裡並經審核，每次判綠時，在同一個 commit 於不受影響的環境（例如會跑同一個檢查的 CI；不是另找的存放位置，見 progress-record「位置」）重跑通過；例外以外的失敗清單要是空的。
WARNING 記入變更摘要；brownfield 的既有債務依 project-init 的既有專案導入指南處理。找不到宣告的工具時停下回報，
不自行換成其他命令。檢查失敗時，在技術訊息後補一句白話說明，並告訴人類不需要處理。
品質分層不得省略已宣告的 ssot、security validators；docs 仍只在有 `mkdocs.yml` 時執行。
其他語言要列出工具缺口；沒有對應的檢查工具時，不能以現有守衛通過宣稱全面支援，人工審查也不能代替已要求的工具。

## 步驟11｜全系統冒煙測試

執行專案宣告的冒煙測試；相同輸入的全體回歸已涵蓋全部適用冒煙測試時可引用該結果。
失敗時找出受影響模組，回步驟6 修正後重跑步驟7、9、11。
