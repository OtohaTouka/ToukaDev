### 安全性檢查清單

AI 逐項比對本次 Gherkin 場景和實作計畫：

#### 【身份驗證與密碼】
觸發條件：任何涉及登入、註冊、帳號、密碼、身份驗證的功能

```
□ 密碼是否使用 bcrypt / argon2 / scrypt 雜湊後儲存？
  ❌ 禁止：明碼儲存、MD5、SHA1
  ✅ 正確：bcrypt（Python: bcrypt 套件；JS: bcryptjs）

□ 登入失敗是否有次數限制？
  ❌ 禁止：無限次嘗試
  ✅ 正確：連續失敗 5 次鎖定帳號或加入延遲

□ Session token / 一次性碼是否用密碼學安全的隨機來源？
  ❌ 禁止：時間戳、使用者 ID、`random` 模組（非密碼學，可被預測）
  ✅ 正確：`secrets.token_urlsafe()`／`secrets.token_hex()`／`uuid.uuid4()`，或框架內建 session／JWT
```

觸發時 AI 輸出：
> ⚠️ **安全提醒｜密碼處理**
> 這個功能涉及密碼，實作計畫已採用 [bcrypt/argon2]。密碼絕對不能明碼儲存，即使是測試資料也不行。

---

#### 【前端資料儲存】
觸發條件：任何涉及前端儲存使用者資料、token、狀態的功能

```
□ 敏感資料是否避開 localStorage？
  ❌ 禁止放進 localStorage：JWT token、使用者密碼、個人資料、權限資訊
  ✅ 可以放：非敏感的 UI 偏好設定（深色模式、語言）
  ✅ token 應放在：httpOnly cookie（後端設定）

□ 資料是否明碼儲存？
  ❌ 禁止：任何敏感資料明碼放在前端可讀取的位置
```

觸發時 AI 輸出：
> ⚠️ **安全提醒｜前端儲存**
> 這個功能涉及前端資料儲存。JWT token 和使用者資料不能放進 localStorage，因為任何 JavaScript 都可以讀取，XSS 攻擊會直接拿走。實作計畫已改用 httpOnly cookie。

#### 【資料庫查詢】
觸發條件：任何涉及資料庫讀寫、搜尋、篩選的功能

```
□ 是否使用參數化查詢或 ORM？
  ❌ 禁止：用字串拼接 SQL（f"SELECT * FROM users WHERE name='{name}'"）
  ✅ 正確：SQLAlchemy ORM、參數化查詢（?或:param）

□ 查詢結果是否有限制筆數？
  ❌ 禁止：SELECT * 無限制返回
  ✅ 正確：加上 LIMIT，避免資料庫被查爆
```

觸發時 AI 輸出：
> ⚠️ **安全提醒｜資料庫查詢**
> 這個功能涉及資料庫查詢。實作計畫已使用 ORM／參數化查詢，避免 SQL injection。

#### 【API 端點】
觸發條件：任何涉及新增、修改 API 端點的功能

```
□ 新端點是否有身份驗證保護？
  ❌ 禁止：任何人都能呼叫的寫入端點
  ✅ 正確：需要有效 token 才能存取

□ 是否有基本的輸入驗證？
  ❌ 禁止：直接使用使用者輸入，不做任何驗證
  ✅ 正確：檢查資料型別、長度、格式（FastAPI 的 Pydantic 自動處理）

□ 錯誤訊息是否洩漏系統資訊？
  ❌ 禁止：把 stack trace 或資料庫錯誤直接回傳給使用者
  ✅ 正確：統一的錯誤格式，細節只寫進 log
```

觸發時 AI 輸出：
> ⚠️ **安全提醒｜API 端點**
> 這個功能新增了 API 端點。實作計畫已加入身份驗證檢查和輸入驗證。

觸發條件：任何涉及 API 金鑰、密碼、設定、憑證的功能

### AI 禁止行為

- ❌ 跳過安全性檢查直接到審核點
- ❌ 觸發了安全風險但在實作計畫裡用不安全的方式實作
- ❌ 用嚇人的方式描述風險（目標是讓小白理解，不是讓他們放棄）
- ❌ 說「你可以考慮加上安全性」——有觸發就必須在實作計畫裡處理，不是建議

### 自動守衛 vs 人工 gate：誰擋什麼

本清單是「**規劃階段**的人工 gate」（AI 對照 Gherkin 提醒）；落地後另有 `scripts/guard_security.py`（S1–S9）做「**程式碼階段**的自動守衛」。兩者互補——守衛擋「明顯做錯」，gate 判斷「做得夠不夠好」：

| 項目 | 自動守衛 guard_security.py | 仍需人工 gate 判斷 |
|------|---------------------------|-------------------|
| 金鑰進 code/git（S1） | ✅ 已知格式＋高熵掃描、.gitignore、.env 追蹤 | — |
| .env.example 同步（S2） | ✅ key 比對＋範本值熵檢查 | — |
| SQL 拼接（S3） | ✅ execute() 吃 f-string／＋／%／.format | 查詢是否加 LIMIT |
| localStorage（S4） | ✅ setItem 敏感 key | — |
| 寫入端點認證（S5） | ✅ 缺 Depends 認證且不在 PUBLIC_ROUTES | **認證是否真的有效** |
| 錯誤洩漏（S6） | ✅ debug=True、detail=str(e) | 是否有統一錯誤 handler |
| 弱雜湊（S7） | ✅ 密碼語境 md5/sha1 | **密碼是否真的先雜湊再存** |
| 自造 token（S8） | ✅ 敏感語境用 random | 框架 session 設定是否正確 |
| 無 schema 輸入（S9） | ✅ request.json() 原始 dict | **驗證規則是否夠嚴**（長度/格式/範圍） |
