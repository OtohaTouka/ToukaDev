# 進度紀錄與暫存清理

本檔是進度紀錄格式、進度網頁與暫存清理的正本。主代理代審時，主代理依本檔維持本機進度紀錄；
原四模式沒有進度紀錄，但同樣登記與清理暫存，暫存項目與各自的清理結果列在最終回報。
進度紀錄是工作檢視，不是 current，也不是授權；正式狀態仍依規則寫進 HANDOVER。

## 位置

- 紀錄：`.toukadev/progress/<任務代號>.md`；總覽板：同資料夾的 `index.md`（見「總覽板」）；網頁：同資料夾的同名 `.html` 與總覽 `index.html`。
- 暫存檔：`.toukadev/tmp/<任務代號>/`。暫存檔指 AI 自己建立的檔案，例如腳本、log、比對用的副本，以及 AI 用指令
  建立的拋棄式 repo。並行的單位各用自己的 `<單位>/` 子資料夾。
- 宿主規定的暫存區照宿主規則使用；並行時照單位分子資料夾；那個資料夾照樣在暫存項目登記一筆
  （類型「其他」、狀態「保留」、備註「宿主管理」）。腳本、log、證據、驗證用複本與其他匯出複本照上一項放本任務暫存資料夾。
- 驗證用複本（審查或重跑測試用，不改版控檔、不 commit、不 push；跑測試產生的快取不算改檔）用 `git clone --no-hardlinks --no-checkout <主要專案資料夾> <位置>`，
  候選是 commit 時再 `git -C <位置> checkout --detach <commit>`，是 tree 編號時再 `git -C <位置> read-tree -u --reset <tree>`：
  有自己的 `.git`，刪除時不牽動主 repo；不用 `git archive` 這類沒有 `.git` 的匯出。
  工具放在這裡仍會誤判時，不另找存放位置；那個專案修好前遇到就停下問人類。
- 工具與測試自己的快取和暫存（例如 uv、pip、ruff、pytest 的）不算暫存檔：照專案設定或工具預設的位置，不為了避開
  工作資料夾或放進 `.toukadev/tmp/` 而把快取改放到別處。系統暫存（TMP、TEMP）也一樣，不指進 repo（含
  `.toukadev/tmp/`）：依賴 git 的測試會往上找到真 repo 而誤判。工作資料夾裡的這類快取，在清理前檢查認得的可重建快取
  名單內（見下方第 2 種）就跟著工作資料夾一起清，名單外的照下方規則問人類；系統暫存區裡的由工具自己輪替清除；
  其他留下的照「收尾」，只提醒人類位置與大小。
- 審核協議 §6.1 的暫時 index 依其規定放在 git 目錄或系統暫存資料夾，用完即刪，不受本檔暫存位置與四種清理項目的限制。
- 工作資料夾：`.toukadev/worktrees/<任務代號>-<單位>/`，或工具自己管理的位置；不得放在 `.toukadev/tmp/` 底下。
- 對話開在工具自己管理的工作資料夾、寫不進主要專案資料夾時，紀錄先放那個工作資料夾的 `.toukadev/progress/`；那裡被 git 忽略，不在任何分支裡，工作資料夾刪了就沒了。總覽板的「其他專案」列路徑，封存對話或移除工作資料夾前把紀錄複製到主要專案資料夾；這兩件事由能寫主要專案資料夾的對話代做，做不到就告訴人類。
- 已建好 venv 或 `node_modules` 的工作資料夾不搬、不改名（裡面的啟動器寫死路徑）；不同任務就新建工作資料夾。
- 跨任務的長期筆記不放 `.toukadev/tmp/<任務代號>/`，任務收尾會連資料夾一起刪。
- 任務代號只用小寫英數與 `-`，且不得為 `index` 或 `archive`（`index` 保留給總覽，`archive` 保留給總覽板的封存資料夾）；新任務代號不得與 `.toukadev/progress/`
  或 `.toukadev/tmp/` 裡已有的名稱重複。
- `.toukadev/` 不進版控；專案尚未忽略時，主代理把它加進用 `git rev-parse --git-path info/exclude`
  取得的檔案（只影響本機，不改版控檔案）。
- 告訴人類的路徑一律寫完整；macOS 上 `.toukadev` 預設隱藏。

## 紀錄格式

- 第一行 `# <任務名稱>`；接著一行 `任務狀態：進行中` 或 `任務狀態：已結束`。舊紀錄多一行 `更新時間：` 不影響顯示。
- 必要區段：`## 需要你決定的事`、`## 工作清單`、`## 審核紀錄`、`## 暫存項目`、`## 尚未驗證與已知問題`。其他區段可有，原樣顯示。
- `## 需要你決定的事`：只放編號項目，一件一項：要決定什麼、建議、不決定的影響、沒回覆時怎麼做；選項寫成縮排的子項目。
  編號不重用：項目移除後，其他項目不重排，新項目用新的號碼。沒回覆時只能照人類核准過的預設做；沒有核准過的預設，
  或屬於 planning 3-4 不套用預設的事（逐次同意項目、停止線、受保護規則的移除或弱化、專案要求更嚴格的同意），
  寫「回覆前這部分暫停，先做其他不受影響的工作」。人類回覆後，把結果連同編號代表的內容抄進審核紀錄，再從清單移除：
  整項移走，不留括號說明或刪除線。沒有就寫「目前沒有。」（可附括號說明）。
  不是編號項目的段落或 `-` 清單照樣算待決（寧可多算），總覽標「格式待修，可能是待決」並列格式警告。
- `## 工作清單` 表頭：`| 項目 | 狀態 | 負責 | 審核者 | 工作分支 | commit | 備註 |`。
  - 工作清單照預計的做事順序排：網頁的「下一步」取第一個「待辦」。
  - 狀態值：待辦、執行中、待審、審核中、退回修正、已驗收、已合併、已完成、已移出（可在值後加括號說明）。
  - 執行者產出的項目只用「已驗收」「已合併」表示完成（網頁打 ✔）；「已完成」只用於審核、人類決定與主代理自己的非產出步驟（網頁顯示中性「完成」，不打勾）；「已移出」用於工作搬到另一份紀錄繼續，備註開頭寫「移到 <任務代號>」（網頁中性顯示，「完成 x／y」的 x、y 都不算這一列）。
  - 開 PR 時，那一列的備註寫完整 PR 網址，「工作分支」欄寫 PR 的分支。
- `## 審核紀錄` 表頭：`| 時間 | 關卡 | 審核對象 | 寫的人 | 審的人 | 結論 | 備註 |`（每列一兩句摘要；完整欄位依 review-protocol §8.3）。
- `## 暫存項目` 表頭：`| 項目 | 類型 | 位置 | 建立者 | 狀態 | 備註 |`；類型：工作資料夾、本機分支、遠端分支、暫存資料夾、其他；狀態：使用中、已清理、保留（備註寫理由）。
  遠端分支的位置寫成 `<遠端>/<分支>`（例如 `origin/wt/x`）。
- `## 尚未驗證與已知問題`：條列。
- 表格每格只寫一兩句，細節放 PR 說明或 ADR；人類原話、同意與判決依據照留在紀錄，不搬、不改短。
- 同意與決定只認人類在本對話的回覆；別的對話（含另一個主代理或執行者）轉來的人類原話只當紀錄、標明來源，
  不當同意或決定，需要時請人類在本對話回答。抄別的對話的原話要從該對話的紀錄取得並附時間，只找到沒有時間的片段就寫「未核對」。
  同一個主代理任務換對話續行時，照 delivery.md 步驟 12 換對話的規定，核對這份進度紀錄記下的原話續行，不算別的對話轉來；
  紀錄裡標明是轉來、只當紀錄的原話，續行時照樣只當紀錄。

完整範例見 `assets/progress/example.md`。只在主代理驗收後才把執行者的項目標為「已驗收」。

人類核准計畫時，主代理把計畫的全部工作項目列成待辦。之後在派工、收件或送審（標「審核中」）、審核有結論、需要人類決定、合併、建立或清理暫存、開始等外部事件時更新紀錄；任務結束時把「任務狀態」改為「已結束」。
合併後被叫醒時、任務結束前、向人類回報進度前，各跑一次比對（見「比對實際狀態」），看到對不上就當場處理。
紀錄與本任務暫存裡的計畫、筆記，實際時間一律取系統時間（例如 `date`），不用估的、不寫「20:1x」這種佔位；預計時間（例如等待預計多久）寫明「預計」；新的一列接在表格最後；先取時間再寫列；直接編輯紀錄文字，不臨時寫程式產生（唯一例外是「比對實際狀態」的 `--apply`）。
人類用編號或代號回覆時，審核紀錄同時寫下每個編號代表的內容；一份給人類的決定清單（例如一頁計畫）涵蓋幾個任務時，每個任務的進度紀錄各抄自己的部分，不只連到別的任務的暫存；在別的對話執行的任務，核准不延伸過去，由人類在那個對話再核准一次。

## 總覽板

- `index.md` 只寫跨任務的事：任務順序、之後的候選、跨任務提醒、不屬於任何任務的待辦。各任務的現況、下一步與要人類
  決定的事由網頁從紀錄彙總，不抄進來；屬於某個任務的事寫進那份紀錄的「需要你決定的事」。
- 總覽板由主代理寫。任務開始、結束、順序改變、候選增減時更新，任務結束時拿掉它做完的候選；和紀錄一樣直接編輯文字，
  不用臨時程式整段改寫，改完核對沒打算動的段落都還在（例如比對改前改後的標題）。改完重產總覽。
- 總覽板上已回覆的事只留最近 7 天；較舊的移到 `.toukadev/progress/archive/` 裡的檔案（網頁不讀這個資料夾；
  和總覽板一樣直接編輯）。
- 檔名 `index.md` 不分大小寫。第一行 `# <標題>`，沒有時顯示「總覽板」；其餘 `##` 區段原樣顯示，不檢查格式。
  總覽板本身讀不到時，算有網頁沒產生（exit 1）。
- 可以有 `## 其他專案` 區段，每行只放一個其他專案 `.toukadev/progress` 資料夾的絕對路徑，不加清單符號或反引號；
  寫錯的那行略過並顯示原因。那些專案的項目一起放進彙總，標出是哪個專案；讀不到時只顯示原因，不影響結束代碼。
  讀取只限：
  1. 只接受絕對路徑，而且是存在的資料夾，最後兩段是 `.toukadev`、`progress`；
  2. 只讀直接底下的 `*.md`，不遞迴；
  3. 連結、junction、reparse point 一律略過，並顯示原因；
  4. 不讀對方的 `index.md`，只讀任務紀錄；兩邊互相列對方時不會遞迴，也不會重複；
  5. 只讀不寫，不替對方重產網頁；連到對方已有的 `.html`，不存在就只顯示文字；
  6. 內容和自己的紀錄一樣全部跳脫；
  7. 路徑只寫在不進版控的總覽板；測試與 ADR 只用假路徑。

## 產生網頁

每次更新紀錄後，從 dev-workflow Skill 的實際安裝根執行：

```text
python <dev-workflow 安裝根>/assets/progress/render_progress.py <紀錄檔或 .toukadev/progress 資料夾>
```

- 安裝根依目前環境的 Skill 目錄或 catalog 解析，與解析其他 sibling Skill 的方式相同；
  不依賴下游專案裡的 ToukaDev repo。
- 程式需要 Python 3.12 以上，只用標準函式庫。找不到安裝根或跑不起來時，告訴人類原因；
  `.md` 紀錄照樣可讀。
- 每份紀錄旁產生同名 `.html`，資料夾內產生總覽 `index.html`；都先寫暫存檔再替換，不會留下寫一半的網頁。
- 給單一紀錄執行時，也會重產同資料夾的總覽 `index.html`；其他紀錄的網頁不重產。只給總覽板 `index.md` 時，
  只重產總覽（exit 0）；給整個資料夾時，`index.md` 當總覽板讀，不列為略過。
- 只處理 `.toukadev/progress` 資料夾或其中的 `.md`；給其他位置會拒絕（exit 2）。
- 產生的網頁帶有產生器標記。遇到沒有標記的同名 `.html`（例如舊版程式產生的，或不是本程式產生的檔案），
  程式不會覆寫（exit 1）；這時請人類決定要不要刪掉那個檔案，AI 不可自行刪除。
- 結束代碼：exit 0 是全部產生完成（有格式警告也是 0，警告顯示在網頁上）；exit 1 是有網頁沒有產生或沒有覆寫；
  exit 2 是位置或參數不對，或 Python 版本太舊。exit 0 以外都要把程式印出的原因告訴人類。
- 程式印出格式警告時，當場修正紀錄再產生一次；修不了的（例如「其他專案」的紀錄，這裡只讀）照實留著。
- 網頁只讀本機、不連網，用一般瀏覽器開啟時每 5 秒自動重新整理。它是同一份紀錄的另一種呈現，
  不是第二份正本；兩者不同時以 `.md` 為準。
- 某些工具（例如 Claude 桌面版的內建瀏覽器）只把本機檔案顯示成快照，不會自動更新；網頁會顯示提醒。
  要看即時進度，請用一般瀏覽器開 `index.html`。

## 網頁會顯示什麼

網頁本身會顯示各區的說明與提示；這裡只列判讀時要知道的事。

- 「畫面更新於」是網頁最近一次載入的時間，「紀錄最後更新」是紀錄檔（`.md`）的修改時間，兩者不同。只顯示快照的工具
  會標「此畫面不會自動更新」；選取文字時暫停自動更新；主題按鈕依序切換跟隨系統、淺色、深色。
- 任務「進行中」時，紀錄超過 30 分鐘沒更新變黃、超過 120 分鐘變紅；「需要你決定的事」有內容時改顯示「等你決定」。
  過期提示分不出長時間工作與忘了更新，人類要確定時直接問主代理。
- 總覽最上方自動彙總：「要你決定」逐項列出每份紀錄「需要你決定的事」的最上層項目並附連結（已結束的任務照列，直到
  項目移除；寫「目前沒有」的不列；不是編號項目的照列並標「格式待修，可能是待決」）；有格式警告時接著列「格式警告」，
  寫每個任務（含其他專案）的件數；「現在／下一步」列出進行中紀錄裡狀態是執行中、待審、審核中、退回修正的項目與
  備註，再加上第一個「待辦」。總覽板內容接在彙總下面；每個任務頁上方也顯示該任務的現在／下一步。
- 進行中的紀錄，工作清單至少一列而且都完成（已驗收、已合併、已完成、已移出），暫存也都已清理或保留時，「現在／下一步」
  與總覽那一列標「可能可以標已結束」。這是提示，不是格式警告；確認沒有剩下的事就把任務狀態改成「已結束」。
- 資料夾裡有 `sync-status.json`（見「比對實際狀態」）時，總覽最上方先列「和實際狀態對不上」：對不上的逐項列出，
  沒比對與查不到的收合在下面，附比對時間；比對之後有紀錄改過、新增或不見時，標「比對後紀錄有改過，結果可能過時」。
  沒有這個檔就不顯示；檔案是連結、太大或格式不對時只顯示原因。內容一律跳脫、不產生連結；網頁照舊不連網。
- 審核紀錄超過 10 列時，任務頁只展開最近 10 列，較早的收合在上方（按一下展開）；展開狀態只記在這個瀏覽器分頁，
  自動重新整理後照舊。
- 總覽顯示總覽板的最後更新時間；有「已結束」的紀錄比總覽板新時，提示「總覽板可能過期」。這是近似判斷：已結束的
  任務事後再改也會觸發，更新總覽板後提示就消失。
- 表格照紀錄的表頭顯示所有欄位；✔ 只出現在已驗收、已合併，已完成顯示中性「完成」，已移出中性顯示、不算進「完成 x／y」。暫存項目醒目顯示「未清理 N 項」；
  任務已結束時，有寫理由的保留不算未清理，另外列件數，但備註去掉前後空白後以「等你決定」開頭的照舊算未清理、標醒目；
  總覽每個任務一列，「進度」寫「完成 x／y」。
- 格式警告只有八類：缺必要區段、必要區段寫了不只一段（「需要你決定的事」合併成一段，每段的待決都照算；其他的後面那段
  照原樣顯示在最下面）、狀態值不在規定清單內、「已移出」的備註開頭不是「移到 <任務代號>」、審核紀錄的時間、已結束的紀錄有上一點那種「等你決定」的
  保留，「需要你決定的事」卻寫「目前沒有」或沒有項目（清理清單見「收尾」）、「需要你決定的事」有不是編號項目的待決，
  以及進行中的紀錄有表格格子超過約 200 字。格子字數只查工作清單、審核紀錄、暫存項目各自的第一張表；寫成
  「原話：「…」」的人類原話不算字數，引號沒收尾時從那裡到格子結尾都不算（原話本身引號不成對時才不會一直警告）。
  時間只查任務「進行中」的紀錄裡
  寫成 `M/D HH:MM` 或 `YYYY-MM-DD HH:MM` 的格子：某列比上一列早，或比紀錄檔的修改時間晚 2～59 分鐘時警告；
  只寫月日時取修改時間那年，算出來比修改時間晚超過 30 天就當成前一年。
  混用本機與 UTC 的時間會出現順序警告，改用同一個時間來源。看到警告就修正紀錄。

## 比對實際狀態

紀錄靠人記得更新，合併、刪分支這類外部事件常沒跟上。比對程式只讀、不改紀錄，從 dev-workflow Skill 的實際安裝根執行
（安裝根的解析方式與「產生網頁」相同）：

```text
python -I <dev-workflow 安裝根>/assets/progress/sync_progress.py <.toukadev/progress 資料夾>
```

- 只比對這個資料夾直接底下的任務紀錄，不讀總覽板的「其他專案」。git 指令在紀錄所屬的專案裡跑；工作資料夾的相對路徑
  從主要工作資料夾（`git worktree list` 的第一筆）算起。
- 只用唯讀指令（git 的 rev-parse、remote、config --get、worktree list、symbolic-ref、ls-remote、show-ref，與 `gh pr list`），
  不 fetch、不 prune；每個指令有時限、關掉登入提示。ssh 遠端不問密碼；自己設了 `GIT_SSH_COMMAND`、`GIT_SSH` 或
  `core.sshCommand` 時照你的設定跑，只靠時限。
  需要 Python 3.12 以上；沒裝 `gh`、沒登入或沒網路時那幾列寫「查不到」，和「不存在」分開。
- 工作清單以「工作分支」欄認 PR，PR 網址只從備註讀。repo 取自備註裡唯一的完整 PR 網址；沒有網址時，只有專案剛好一個
  GitHub 遠端才用它。不查的列：狀態是「待辦」又沒有網址的，以及已經是已合併、已完成、已驗收或已移出的（不會對不上）。
  查到的 PR 要剛好一個、不是從 fork 開的、分支一致，有網址時就是網址那個，才比對；其他情況寫「沒比對」，只有
  「查到 0 個 PR 又沒網址」（還沒開 PR）不列。對不上：PR 已合併，狀態卻不是已合併、已完成、已驗收或已移出；
  PR 已關閉沒合併，狀態還是待審或審核中。
- 遠端分支的位置寫成 `<遠端>/<分支>`，第一段等於現有的遠端名才當成遠端；只寫分支名時，只有專案剛好一個遠端、而且是
  這份紀錄工作清單用到的分支才比對。位置看不懂時改看項目欄，從項目欄認出來的只偵測。同一份紀錄裡這個分支的
  PR 網址指向別的 repo 時，寫「沒比對」。用 `git ls-remote` 讀遠端目前的 commit：分支確定不存在、狀態卻不是已清理；
  或狀態是使用中，而且符合第 4 種清理項目的前三個條件（不是預設或共用分支、PR 已合併、遠端目前的 commit 等於合併時
  的 head），都算對不上（後者應改保留，由人類決定刪不刪）。合併後又有新 commit 的寫「沒比對」，不算可以刪；預設或
  共用分支、遠端不是 GitHub 的使用中列也寫「沒比對」。預設分支只在其他條件都符合時才查（本機沒有 `<遠端>/HEAD`
  時問遠端），查不到寫「查不到」。repo 名稱不分大小寫。
- 工作資料夾要 git 的工作資料夾清單和磁碟上都沒有才算不存在，只有一邊沒有時寫「沒比對」。位置只認不含空白與全形字的
  路徑，網址與網路路徑（`\\host\share`）不碰。本機分支只看 `git show-ref`，只偵測。分支名只認英數與 `._/-`；
  位置不是路徑或分支名的列不猜：狀態已清理就不列，其他寫「沒比對」。
- 反過來，寫已清理，但遠端分支、工作資料夾或本機分支還在的，也算對不上（只偵測）。
- 另外直接查 `git worktree list` 的全部項目（不靠紀錄有沒有登記）：落在 `.toukadev/tmp/` 底下的工作資料夾列成整個專案的
  「對不上」，`--apply` 不改它。四種自動清理都清不掉它，不自動刪：驗證或重現用的複本照「驗證用複本」重建，舊的列進清理清單
  交人類；實作用的工作資料夾沒有 venv、`node_modules` 就用 `git worktree move` 搬到 `.toukadev/worktrees/`，有的問人類。
  搬之前確認沒有執行者或程式還在用它；搬完當場把暫存項目那一列的位置改成新位置，不留給 `--apply`（舊位置不在了，它會改成已清理）。
- 結果印在畫面上，也寫進同資料夾的 `sync-status.json`（格式見 `docs/ssot/README.md`；先寫暫存檔再替換），網頁最上面顯示；
  紀錄超過 500 份時不寫，請先把舊紀錄搬走。結束代碼：0 沒有對不上也沒有查不到（只有「沒比對」的列也是 0）；1 有對不上、
  查不到、讀不到紀錄、寫不進結果檔或 `--apply` 被拒絕；2 位置或參數不對、Python 太舊。
- 抓不到沒照這些寫法的舊列，也不看路線圖；工作搬走後原列沒關的，靠「已移出」避免。「已移出」只檢查備註的任務代號
  格式，不檢查那份紀錄在不在。專案有兩個以上 GitHub 遠端時，沒寫 PR 網址的列都比對不了。

合併後的固定欄位，只有主代理可以用同一支程式更新自己負責的那一份紀錄（「直接編輯紀錄文字」的唯一例外）：

```text
python -I <dev-workflow 安裝根>/assets/progress/sync_progress.py <.toukadev/progress 資料夾> --apply --task <任務代號>
```

- 判斷條件和上面的比對相同，判讀不了或查不到的列不改。只改三種固定欄位：
  1. 工作清單：備註有完整 PR 網址、PR 屬於這個專案的 GitHub 遠端（不是 fork）、PR 的分支等於「工作分支」欄的列，
     狀態改「已合併」，備註最後加「PR 已合併 M/DD HH:MM（合併 commit 前 8 碼）」；
  2. 遠端分支：位置寫明 `<遠端>/<分支>`（或只有一個遠端時的分支名），而且同一份紀錄有這個分支屬於那個遠端的 PR 網址：
     符合前三個條件、狀態是使用中 → 改「保留」，備註開頭加「等你決定：已合併，可以刪。」；分支確定不存在 → 「已清理」；
  3. 工作資料夾確定不存在、而且它的上一層資料夾還在 → 「已清理」。本機分支不改。
- 審核紀錄最後加一列：關卡「自動比對」、寫的人「sync_progress」、審的人「—」、結論「已更新」，備註寫改了哪幾列。
  任務狀態、需要你決定的事、審核結論、備註原本的字、其他紀錄、總覽板與路線圖都不改。
- 寫入前核對要改的那一行就是比對時的那一列、新舊內容只差目標格子與新加的那一列；讀檔後內容被改過就整個放棄。
  保留原本的編碼（UTF-8，有無 BOM）、換行與檔案權限；只寫一般檔案，連結拒絕；紀錄裡有特殊換行字元（例如 U+2028）、
  或要改的表格在圍欄（```）裡時不改。紀錄超過 500 份時改之前就停；寫結果檔失敗時照樣列出已改的列。
  剩餘風險：最後一次核對到替換之間仍有極短的空檔，和刪除程式同樣接受。
- 已知限制：帶工作分支與 PR 網址的審核步驟（例如 DEV-B 那一列）也會被改成「已合併」，不是「已完成」；
  工作資料夾的名稱打錯、但上一層資料夾存在時，會被改成「已清理」。
- 臨時寫的程式照舊不准改紀錄。

## 暫存清理

### 登記

- 建立工作資料夾、本機分支、遠端分支或暫存資料夾時，立刻登記到「暫存項目」，狀態寫「使用中」。
- 派工時在「暫存位置」欄寫明執行者的暫存位置；執行者在回報中列出自己建立的項目，由主代理登記。

### AI 可自動清理的項目

只有下列四種，而且只用其中規定的安全刪法。前三種刪除前，先執行同一個 Skill 的清理前檢查程式
`assets/progress/check_cleanup.py`（安裝根的解析方式與「產生網頁」相同）。

- 在主要專案資料夾（repo 根）執行；在工作資料夾裡執行會被拒絕。
- 程式只檢查、不刪除：全部條件符合時印「可以清理」並以 exit 0 結束；不通過時列出原因並以 exit 1 結束；
  參數錯誤或 Python 版本太舊時以 exit 2 結束。只有 exit 0 才刪，其他一律問人類。
- 檢查程式說可以，AI 才刪；說不行或程式跑不起來，就問人類。

1. **本任務建立並登記的暫存資料夾**：本任務自己的 `.toukadev/tmp/<本任務代號>/` 這一層。
   - 不能是 `.toukadev/tmp/` 本身或其他任務的資料夾；路徑解析後必須正好等於這一層。
   - 先執行 `python <dev-workflow 安裝根>/assets/progress/check_cleanup.py tmp <路徑> --task <任務代號>`。
   - 刪除前先用 `git worktree list` 確認沒有任何工作資料夾落在裡面；有就停下問人類。
   - 檢查程式也查 `.toukadev/lessons/` 直接底下、狀態是待處理、保留觀察或認不出狀態的流程紀錄：還引用這個暫存資料夾
     （兩種分隔、不分大小寫、比到任務代號結尾）就不通過。被擋時先把紀錄的證據改指會保留的位置再重跑，做不到才問人類。
   - 只用同一個 Skill 的 `assets/progress/delete_tmp.py` 刪除：Python 3.12 以上的 `shutil.rmtree`，不跟著 symlink／junction 走；在 Windows 上只把這一層裡確實被設成唯讀的一般檔案取消唯讀再刪。規定刪法包含這一項處理；其餘照下方。
2. **本任務的 AI 自己用 `git worktree add` 建立並登記的工作資料夾**：
   - `git worktree remove` 即使不加 `--force`，也會直接刪掉被 git 忽略的內容（例如 `data/`、`.env`）、
     順著工作資料夾裡的 junction 刪到外部內容，並丟掉 detached HEAD 上的 commit，所以不能直接用。
   - 先執行 `python <dev-workflow 安裝根>/assets/progress/check_cleanup.py worktree <工作資料夾> --branch <分支>`。
     它確認：是本 repo 在 `.toukadev/worktrees/` 下的工作資料夾；HEAD 在指定分支上；沒有改動或未追蹤檔；
     被忽略的只有可重建的快取（`.venv`、`.uv-cache`、`.ruff_cache`、`.pytest_cache`、`.mypy_cache`、
     `__pycache__`、`node_modules`）或專案宣告的建置產物（見下一項）；捷徑連結只允許可重建快取裡面的 POSIX symlink（Linux／macOS 的
     `.venv` 本來就含 symlink），快取以外的任何 symlink、快取資料夾本身是連結，以及任何 Windows junction
     或 reparse point（包含 Windows 上的 symlink）都不通過。工作資料夾裡也不能有另一個 repo 的 `.git`
     （不分大小寫）；快取裡 uv 這類工具放的空白 `.git` 標記檔不算 repo。
   - 建置產物宣告：專案在 repo 根目錄放 `rebuildable-outputs.txt`（UTF-8 一般檔，不能是 symlink），每行只能是空行（不能
     含空白），或一個從 repo 根算起的相對路徑本身（例如 `web/dist/`），不能有註解、清單符號或反引號；被忽略的項目
     等於某個宣告路徑或在它底下才算。檢查只讀 `origin/HEAD` 指到的預設分支上的這個檔，沒有這個檔就是沒有宣告；它和
     任何已登記工作資料夾（不含主要專案資料夾）的分支同名時不採用。讀不到或任何一行不合法，整份當沒有宣告，照舊擋下
     問人類，不改讀其他分支；不合法的重點有空、`.`、前後有空白、看不見的字元、行尾註解（空白後接 `#`）、絕對路徑、
     含 `..` 或 `\`、萬用字元、`#` 開頭的段、`.git` 或 `.toukadev` 段、可重建快取名單裡的名稱（已是快取，不必宣告）、
     路徑本身沒被 git 忽略，其他格式錯誤也算，錯誤訊息會指出哪一行、什麼原因。檢查輸出有「已採用宣告」時，清理前先
     `git fetch origin` 再跑一次檢查；fetch 或重跑失敗就問人類。沒有採用宣告時不必 fetch。列出的路徑本身或底下的
     symlink、junction、reparse point、空白 `.git` 標記、巢狀 repo 與 bare repo 一律擋，不沿用快取豁免，整份不採用時
     也一樣；其他條件與刪法不變。宣告的新增或修改要列進該任務的一頁計畫給人類核准。
   - 檢查通過才用 `git worktree remove`（不加 `--force`）。
   - 工具自己建立或管理的工作資料夾不刪，只提醒人類位置與大小；裡面有進度紀錄時，一併提醒封存前先複製。
3. **本任務建立並登記的本機分支**：
   - 先執行 `python <dev-workflow 安裝根>/assets/progress/check_cleanup.py branch <分支>`。
   - 通過才用 `git branch -d`，不用 `-D`。
   - 不刪預設分支、共用分支與目前所在的分支。
4. **本任務建立、推上去並登記的遠端分支**，下列條件全部符合才刪：
   - 不是預設分支或共用分支；
   - 以這個分支為 head 的 PR 在代管服務上的狀態是已合併（例如 `gh pr view <分支> --json state` 為 `MERGED`）；
   - 用 `git ls-remote <遠端> refs/heads/<分支>` 讀遠端目前的 commit（不用本機可能過時的 `origin/<分支>`），與該 PR 合併時的 head（`headRefOid`）相同；不同代表合併後又有新 commit，問人類；
   - 在人類核准的 Git 範圍內。

   刪除用帶比對的寫法：`git push --force-with-lease=refs/heads/<分支>:<headRefOid> <遠端> --delete <分支>`。
   遠端先比對，內容一樣才刪；這不是強制覆寫。

預設分支與共用分支（其他任務或其他人會使用或接手的分支，例如 dev、main）在本機與遠端都永遠不刪。
其他任何項目、任何條件不確定、檢查不通過、或上述指令失敗時，不強制、不換更強的刪法，改成問人類。
代理平台禁止 AI 永久刪除時，第 1、2 種項目照常跑清理前檢查，但不用規定的刪法，也不換成任何其他刪法（含移到資源回收筒）：
通過的項目列進收尾的清理清單，刪法寫「由你刪除」並附路徑與指令。平台只要求逐次確認時，確認後照規定刪法刪，清理清單寫明那是永久刪除、不能復原。
分支還在工作資料夾裡使用時 `git branch -d` 會失敗，所以先清工作資料夾，再清分支。

### 暫存資料夾的刪法

第 1 種項目只用同一個 Skill 的 `assets/progress/delete_tmp.py` 刪除（安裝根的解析方式與「產生網頁」相同）。

- 在 repo 根執行 `python -I <dev-workflow 安裝根>/assets/progress/delete_tmp.py <路徑> --task <任務代號>`；`<路徑>` 用通過清理前檢查的同一個路徑，不複製腳本，也不放進要刪的資料夾。
- `-I` 讓 Python 不把腳本所在的資料夾和目前資料夾加進模組搜尋路徑、不讀 `PYTHON*` 環境變數，
  repo 裡同名的 `.py` 不會取代標準函式庫。
- 路徑自我檢查：刪之前，程式在同一個程序裡重跑清理前檢查的 tmp 檢查（載入同資料夾的 `check_cleanup.py`，
  不另寫一份）。路徑不是 repo 根下 `.toukadev/tmp/<任務代號>` 這一層、任務代號不合法、檢查不通過，或檢查
  沒辦法完成（包含載入失敗）時，什麼都不刪，以非 0 結束。
- `shutil.rmtree` 不跟著 symlink／junction 走：連結本身刪掉，連結指向的內容不動。
- Windows 上 git 會把 object 檔設成唯讀，`shutil.rmtree` 刪不掉。下列條件全部成立時，程式才取消該檔唯讀再刪：
  - 在 Windows 上；
  - 失敗的是刪檔案的 `os.unlink`（不是刪資料夾的 `os.rmdir` 或其他步驟），錯誤是 `PermissionError`；
  - 兩邊路徑都先 `abspath` 再 `normcase`，用 `commonpath` 確認在 `<路徑>` 這一層底下；不同磁碟算在外面；
  - 用 `os.lstat` 讀到是一般檔案、不是 reparse point（junction、symlink 都是），而且確實有唯讀屬性；
  - 沒有其他硬連結（`st_nlink` 等於 1）。唯讀屬性跟著檔案本身走、硬連結共用，例如本機 `git clone` 會用硬連結
    共用 object 檔；這時取消唯讀會連資料夾外那份一起改掉。
- 取消唯讀時，`os.chmod` 有支援才加 `follow_symlinks=False`。
- 任何一項不成立，或遇到其他錯誤，程式照原錯誤停下，不再往下刪；這時照上方規則問人類。
- 接受的剩餘風險：檢查後到取消唯讀之間，檔案被換成連結的時間差。前提是這個資料夾只有本任務的 AI 在寫。
- 刪除程式只有這一份；改程式就要同步改測試。

### 收尾

- 結束時每個暫存項目都要是「已清理」或「保留」（備註寫理由）；清完才算完成。
- 單位的成果合入任務分支後，就照上方規則清它的工作資料夾。分支等任務分支合進共用分支後再清：`git branch -d` 只刪已合併的分支
  （設了 upstream 時比對 upstream，沒設時比對目前分支）；要更新本機共用分支時只用 fast-forward，不能 fast-forward 就問人類；
  共用分支用 squash 合併時，`-d` 永遠會失敗，照規則問人類。驗證用複本與其他匯出複本，任務結束時隨本任務暫存資料夾一起刪。
- 要保留的證據（例如紅燈 log 摘要、付費實測的逐請求用量、審核包的結論與 HIGH／BLOCKING 的處理）先寫進回報或 PR 說明，
  進度紀錄的審核紀錄寫摘要，再清理。
- 工具自己的快取（例如 Codex 的對話紀錄與工作資料夾、uv 快取）不自動刪除，只在收尾時提醒人類已知的位置與大小。
- 不能自動清的項目，狀態寫「保留」，備註以「等你決定」開頭，寫原因與建議，然後繼續做別的，不停下等回覆。中途可以先把
  這些項目列進「需要你決定的事」順便問一句（例如合計超過約 20 GB 時），不等回覆。
- 收尾時把所有沒清的項目（含有理由的保留）和已知的工具快取列成清理清單，寫成「需要你決定的事」裡的一個編號項目；
  每個子項目寫位置、大約大小、被哪些版控文件或流程紀錄引用（用路徑搜尋 repo 與 `.toukadev/lessons/`）、為什麼不能自動清、建議刪或留。大小量得到就寫，一次量一個資料夾的總大小；項目太多或
  量太久才寫「未量」並說明原因。
- 人類回「全部刪」或挑編號；只刪清單上的項目，沒回覆就都不刪；刪法照本檔，人類同意不代表可以換更強的刪法。清單列好、
  其他項目都已清理或保留，任務就可以標「已結束」。
