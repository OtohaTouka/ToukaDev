# 專案初始化流程（規格驅動開發）

## 核心原則

- **規格優先**：任何目錄或程式碼建立之前，必須先完成需求訪談與技術棧確認。
- **SSOT 從一開始**：文件目錄結構是 SSOT 的基礎，建錯了後面全部都錯。
- **人類審核點**：步驟2後（INIT-A，技術棧）和步驟5後（INIT-B，完整規格）各一個，確認後才繼續。
- **此流程只跑一次**：先區分未初始化、初始化中及已完成；初始化中恢復原步驟，完成後的功能依當次委託使用 `dev-workflow`。

---

## 按需程序

- 規劃新專案時，必讀 [程序](references/requirements-planning.md)。
- 規格通過後建立與驗證骨架時，必讀 [程序](references/scaffold-validation.md)。
- 選用初始化主代理代審時，必讀 [程序](references/supervised-initialization.md)。

小型專案初始化的適用性與省略項目在需求程序的步驟0；精簡輸出模式只調整輸出詳細度。
沿用當次偏好，未知時採標準說明，需要新手解說才讀 `references/beginner-guide.md`。
初始化產生的 AGENTS.md 必須保留「Quick validation profile」段的命令清單；
ssot／security／條件式 docs 命令及最近作用域規則不得刪除或替換。

## 步驟前檢查｜已初始化與既有程式碼偵測


開始任何訪談之前，依序做兩項檢查：

### 檢查0｜規則檔名正規化

- 只有正式 `AGENTS.md` → 繼續檢查1。
- 只有舊 `Agents.md` → 暫停，先以暫存名稱執行兩段式改名，再補齊共同規則基線。 <!-- guard: F7-legacy-agents-ok -->
- 同時存在 `AGENTS.md` 與舊 `Agents.md` → 停止流程，列出兩份檔案並請使用者決定保留內容；禁止自動覆蓋或合併。 <!-- guard: F7-legacy-agents-ok -->

舊檔遷移只改檔名與補齊缺少的共同基線，不得覆蓋原專案的技術棧、命令、權限與專屬禁令。

### 檢查1｜有效規則與狀態

空目錄或交班模板不構成已初始化證據；有效規則加有效 current 或 legacy 狀態才可接續。
AGENTS 與 HANDOVER 的存在不代表初始化完成；初始化中回原步驟，明確完成紀錄與成果才支持交棒 dev。
只在需要恢復狀態時按根 HANDOVER.md → docs/handover/CURRENT.md → 完整宣告的 legacy 候選解析。
既存入口無效須回報，不依日期猜測或全文掃描歷史；多個 legacy 候選須明確選擇。
已有初始化來源（如規格或規則）但不完整時，說明缺口，只補當次已授權項目；不得當成全新專案覆蓋。
接續初始化時核對原始委託、已核准規格、精確中斷點及剩餘工作；不因生成規則檔而改走 dev。
既有已完成專案沒有新增狀態欄位時，可用明確完成紀錄與成果判定，不強迫重新初始化。
已完整且要求接續開發時轉 dev-workflow；只有意圖不清或要重新初始化時才詢問並等待明確決定。
指定文件的唯讀問題不因缺初始化文件而強迫 project-init。

### 檢查2｜既有程式碼偵測（brownfield，檢查1無發現時執行）

當前目錄已有實質程式碼跡象——例如 `src/`、`pyproject.toml`、`package.json`、或多個程式檔案——但沒有 ToukaDev 痕跡：

→ 暫停並詢問使用者：

> 「這個目錄已有程式碼，但還沒有用 ToukaDev 管理。你想要：
> 1. **導入既有專案（brownfield）** → 我會盤點現況、反推規格、只補缺的文件骨架，**不動你現有的程式碼**
> 2. 這其實是全新專案（現有檔案只是雜項）→ 繼續標準初始化」

選擇導入 → 改走 `references/brownfield-guide.md` 的 B1–B7 導入流程，不啟用 greenfield 主代理迴圈；完成後列出 dev-workflow 下一步。

### 兩項檢查皆無發現 → 進入步驟0。

## ⏸ 人類審核點 INIT-A｜技術棧

步驟2的可審核技術棧方案與理由完成後，取得人類選擇或單一推薦的明確同意，才進入步驟3。
當次對話已有對應核准即可沿用，不能從歷史推定。

## ⏸ 人類審核點 INIT-B｜完整規格

步驟5完成完整規格、SSOT、介面、安全與驗證規劃後，取得人類確認才可建立步驟6以後的骨架。
品質適用條件、可觀察骨架成果與必要驗證一併納入 INIT-B。只有 INIT-A 通過仍不得開始步驟6。
可在此另列 INIT-B 後主代理委託；規格同意不代表選用。明確選用且兩個 gate 通過後，
依初始化專用程序管理步驟 6–12、範圍內 DBG-A 與最終骨架驗收；未選用沿用原路線。
不由初始化核准推定 Git 或其他後續操作授權。

## AI 禁止行為清單

- ❌ 未通過「步驟前檢查」就開始訪談（不得覆蓋既有來源；不明或重建須先詢問）
- ❌ 在需求訪談完成前建立任何目錄或檔案
- ❌ 在技術棧確認（INIT-A）前繼續步驟3以後
- ❌ 在規格確認（INIT-B）前繼續步驟6以後
- ❌ 建立 .env 檔案（只建立 .env.example）
- ❌ 在 .gitignore 以外的地方提交 .env
- ❌ 跳過 AGENTS.md 和有效 HANDOVER.md 的建立
- ❌ 未經人類確認即採用技術棧（多方案由人類選；單一推薦也必須取得人類同意）
