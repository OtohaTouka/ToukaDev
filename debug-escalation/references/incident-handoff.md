# 事故建立與交棒（步驟 1–2）

新事故建立與交棒時讀取；不在尚未達升級條件時套用。

每次事故使用唯一 incident-id；同日事故不得覆寫，原 FAIL evidence 保留。
事故記錄來源流程與精確中斷點；初始化早期尚無 HANDOVER 時使用當次已授權且可用的產物位置，不提前建立後續骨架。
有可用專案文件位置時，以日期加主題及唯一後綴建立 docs/evidence/<incident-id>.md；
先確認新路徑不存在。已有 current 只放摘要與精確連結；無 current 時由當次交接明列事故位置。

## 步驟1｜當前模型：撰寫除錯交班文件


在上述適用位置建立唯一事故記錄；已有根 HANDOVER.md 時更新狀態與精確連結，不覆寫
同名事故。早期尚無 HANDOVER、tests 或 guards 就據實記錄，不為交班先執行後續初始化步驟。

**必須包含以下所有段落，不得省略：**

## 步驟2｜交棒新的分析上下文

`SUPERVISOR_DELEGATED` 且本次委託有效時，由主代理把事故精確連結、原始 FAIL、已嘗試方向、
來源流程、精確中斷點、驗證能力及剩餘分析輪數交給 Debug 角色。可用子代理、其他對話、CLI 實例或等效方式；優先選擇
適合問題的新分析上下文，不要求一定有更高價模型。同模型新上下文如實標明，換執行者不清零
同一問題的失敗歷史。執行者先完成步驟3–5，再交主代理 DBG-A；主代理不自行代寫方案。

原人類操作路線維持以下通知；有效主代理委託內不要求人類另開 session，也不結束主代理的統籌工作。

交班文件完成後，輸出：

```
⏸ 除錯升級交班文件已完成。

路徑：[本次事故的實際精確位置]

請執行以下操作：
1. 開啟新的 session（或切換到高階模型）
2. 讓新模型讀取上述交班文件
3. 告知新模型：「請執行 debug-escalation Skill，從步驟3開始。」

當前 session 到此結束。
```

### 給新手使用者的具體操作說明

若使用者不熟悉 AI 工具操作，在上述訊息之後補充：

> 「如果你不確定怎麼操作，以下是具體步驟：
> 1. 開啟一個**全新的對話視窗**（不要在目前這個視窗繼續）
> 2. 如果你的工具支援切換模型，請切換到最高階的選項
> 3. 把以下這段話複製貼上到新視窗：
>
> ——————————————
> 請執行 debug-escalation Skill，從步驟3開始。
> 交班文件路徑：[本次事故的實際精確位置]
> ——————————————
>
> 4. 讓新視窗的 AI 繼續處理就好，這個視窗可以關掉了。」
