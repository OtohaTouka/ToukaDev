# 候選

還沒排進工作的想法與已知缺口。有新的流程問題紀錄、或要動到相關規則時再評估；細節在各 ADR。這裡的項目都不是授權。

- 守衛 F1 的 glossary 副本檢查與 F3 的 README 目錄樹檢查沒有單元測試，只靠實際執行守衛（ADR-040 量測）。
- 既有守衛缺口（ADR-040 後果）：F8 只查鎖定句有沒有包含在區塊裡，區塊裡新加「例外：…」照樣通過。要補得改守衛，另行核准。
- 保留觀察（ADR-042；「轉述人類原話的格式」扁平後沒有轉述層，由 ADR-046 結案）：行程只結束自己啟動的；預先授權執行者改既有測試的期望（屬放寬）；
  dev-workflow SKILL DEV-A 的「啟用」單獨讀時容易被讀成核准後才開始 DEV-A（ADR-042 只改 team-roles）。
- 審核規則三個小問題（ADR-043 不採用，沒出過事，出事時再處理）：原四模式已知 `CRITICAL` 時 DEV-B 要不要再提、
  快速路徑停止清單補命令替換、examples 技術棧段對齊範本。
- Linux／macOS 上 tmp 檢查認不出暫存資料夾裡的 bind／FUSE 掛載，刪除會進到裡面（ADR-038；原本就有；要補得改受保護的清理前檢查，另行核准）。
- 新上下文的審查者不必讀整份交班（ADR-050 不採用；省的量在文件分流後已經很小，做文件分流通用化時連同依路徑列規則的腳本再評估）。
- 改進任務的來源（`improvement-run.md`「來源」）目前只寫 HANDOVER 列的待辦，要加上這份候選清單（ADR-050 DEV-B；動到要重裝 improvement-loop，下次改進任務一起做）。
