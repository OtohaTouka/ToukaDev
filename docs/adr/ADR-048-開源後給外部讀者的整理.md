# ADR-048：開源後給外部讀者的整理：共同區塊中性寫法、uv 版本下限與範本釘版

- 日期：2026-10-24
- 狀態：已接受（ToukaDev 開源計畫由人類核准；改共同區塊由人類單獨核准；主代理代審）
- 修訂：ADR-015 D4（uv required version 固定為 0.12.1，CI 從 `pyproject.toml` 讀版本）：`pyproject.toml` 改成下限，
  CI 在 workflow 自己固定版本
- 影響範圍：四份 AGENTS 共同區塊的「溝通風格」與根 `AGENTS.md` 新增的維護者溝通偏好段；`pyproject.toml`、
  `.github/workflows/framework-guard.yml`、新增 `.github/dependabot.yml`；project-init 的四個 CI 範本與 Dockerfile 範本；
  README、新增 CONTRIBUTING、SECURITY；`tests/test_root_toolchain.py`、新增 `tests/test_public_defaults.py`

## 背景

ToukaDev 在 2026-10-22 開源。開源前審查列出幾處對外部讀者不友善、或會被複製到別人專案的地方：

1. 共同區塊的「溝通風格」寫的是維護者個人的溝通偏好：一律繁體中文、語氣隨性、不用客套開場、可以提反傳統方案、
   安全性只在必要時說明。project-init 會把共同區塊原樣複製到新專案，外部使用者的專案也會被要求這樣回覆。
2. `pyproject.toml` 把 uv 鎖成剛好 0.12.1（ADR-015 D4）；裝了較新 uv 的貢獻者連 `uv run` 都跑不起來。
3. project-init 的 CI 範本用沒釘版的 action（例如 `actions/checkout@v4`）、`pip install` 與裸的 `pytest`、`ruff`，
   和 scaffold-validation「一律透過 uv 管理依賴」衝突；Dockerfile 範本用 `uv:latest`。
4. 沒有 CONTRIBUTING、SECURITY，README 沒有英文說明。

## 決定

1. **D1 共同區塊的溝通風格改成中性**：保留「先給答案、提供實際程式碼或原因」「論據要能驗證、推測要標示」「只呈現必要
   上下文」；語言、語氣與詳略改成依專案規則或人類的偏好，都沒寫時用人類使用的語言。維護者的偏好（一律繁體中文、語氣隨性、
   不用客套開場、可以提反傳統方案、安全性只在重要且不明顯時說明）搬到根 `AGENTS.md` 共同區塊外的「溝通偏好（ToukaDev
   維護者）」段，只用在維護本 repo。新測試確認共同區塊不再含這些偏好，根 `AGENTS.md` 的那段還在。
2. **D2 uv 版本**：`required-version` 改成 `>=0.12.1`；CI 不再從 `pyproject.toml` 讀版本，改在 workflow 寫
   `version: "0.12.1"`，CI 照樣可重現。查證（2026-10-24）：uv 0.12.2～0.13.5 的官方 release notes 只有 0.13.0 有
   破壞性變更段落，內容不涉及 lockfile；其他版本提到 lockfile 的都不是破壞性變更。本 repo 沒有用 0.12.1 以外的版本實跑。
3. **D3 Dependabot 版本更新**：只對根目錄的 GitHub Actions 與 uv（pytest、Ruff）開，每月一次，新版發布滿 7 天才提；
   `examples/` 不列（之後會刪）。Dependabot 開的 PR 照 ADR-015 的升級規則審：升 pytest、Ruff 要 DEV-A、lock 更新與
   全量回歸；升 action 也比照辦理（ADR-015 沒列 action，這裡加上）；CI 綠才合。為了讓這類 PR 不必改測試，工具鏈測試改成檢查「每個 action 都釘 40 位 commit SHA
   並註明版本、而且只有 checkout 與 setup-uv 兩個」與「dev 依賴都是 `==` 精確版本」，不再寫死特定的 SHA 與版本號。
4. **D4 project-init 範本**：
   - GitHub Actions 範本：action 釘 commit SHA（和本 repo 的 CI 同版），預設權限唯讀、checkout 不保存憑證、加逾時，
     用 `uv sync --locked` 與 `uv run --locked`。
   - GitLab、Bitbucket、CircleCI 範本：改用釘版的 uv 官方映像 `ghcr.io/astral-sh/uv:0.12.1-python3.12-trixie-slim`
     （2026-10-24 查 GHCR 有這個標籤；同版的 bookworm 標籤不存在），指令一律經 uv。
   - Dockerfile 範本：uv 映像釘 `0.12.1`。
   - Dependabot 只掃 `.github/workflows`，不會更新範本裡的 SHA 與 uv 版本；升級本 repo 的 CI 時手動一起改範本。
   - 新測試確認：範本沒有 `pip install`（含 `pip3`）、沒有直接執行的 pytest／ruff／mkdocs／python、每個 `uv run`／`uv sync`
     都帶 `--locked`；GitLab、Bitbucket、CircleCI 範本都有一行釘版的 uv 官方映像；GitHub Actions 範本的 action 都釘 SHA。
5. **D5 給外部讀者的文件**：README 開頭加英文摘要；新增 CONTRIBUTING（英文為主，附中文摘要）與 SECURITY（用 GitHub 的
   私下漏洞回報）。

## 規則鬆緊

- 放寬：ADR-015 D4 的 uv 版本從「剛好 0.12.1」改成「0.12.1 以上」，CI 仍固定 0.12.1。源頭：ADR-015 為了讓本機與 CI
  用同一套工具鏈；開源計畫核准放寬。
- 放寬：工具鏈測試不再寫死 action 的 SHA 與 pytest／Ruff 的版本號，只檢查格式，仍要求 SHA 釘版與精確版本；換成別的 action
  仍會被擋（測試核對 action 名稱）。理由：Dependabot 的更新 PR 不必每次改測試。
- 不變：共同區塊的工程規則與守衛鎖定的句子都沒動；溝通風格只換成中性寫法。
- 加嚴：project-init 範本的 CI 與 Docker 要釘版並經 uv，由新測試檢查。
- 加嚴：升 action 的 PR 也比照 ADR-015 的升級規則（ADR-015 只列 uv、pytest／Ruff 與 Python minor）。

## 未查證

- Bitbucket Pipelines 用沒有 git 的映像時能不能 clone：官方頁面沒寫。CircleCI 官方文件寫明沒有 Git 與 SSH 時 checkout
  改用完整下載；GitLab 由 runner 自己 clone。
- 四個 CI 範本都只核對內容，沒有在 GitHub Actions、GitLab、Bitbucket、CircleCI 的新專案上實跑。
- Dependabot 自己用的 uv 版本，以及它更新後的 lockfile 在 CI 的 0.12.1 下會不會過。

## 後果

- 用 project-init 建的新專案，共同區塊不再要求繁體中文或特定語氣；維護者在本 repo 的體驗不變。
- 已知限制：還有兩處只適合繁體中文，不在這次範圍：dev-workflow 的 Gherkin 撰寫原則（`planning.md`）寫用繁體中文撰寫，
  mkdocs 範本的 `language` 是 `zh-TW`。要改成依人類使用的語言，另開任務。
- 已用舊共同區塊建好的專案不會自動更新；要中性寫法時照共同基線變更規則，經使用者同意後手動同步。
- 每月最多兩組 Dependabot PR（actions、uv），照 D3 審查。
