# ADR-031：主代理代審與任務範圍自主協作

- 現況：預設模式與寫審分工由 ADR-034 修訂。
- 日期：2026-09-07
- 狀態：DEV-A 人類核准；source 候選待 DEV-B，尚未安裝／試行
- 方案：[實作計畫](../proposal/ToukaDev_Skill_主代理代審與自主協作實作計畫.md)

## 問題

ToukaDev 已有規劃、實作、驗證、退修與 Debug 迴圈，但逐關人類 gate 無法表達使用者想要的
一次委託。把主代理塞進舊 AI_DELEGATED 或 CODEX_NATIVE profile，會混淆嚴格 reviewer
qualification、advisory 與自主驗收，也會帶入不必要的資格及重新核准步驟。

## 決策

新增 optional `SUPERVISOR_DELEGATED`，預設仍 `HUMAN_AI`。模式及舊路線界線由
[review-protocol](../../dev-workflow/references/review-protocol.md) 管理；只有選到新模式才讀
[supervisor-delegation](../../dev-workflow/references/supervisor-delegation.md) 的詳細程序。
主代理負責調度、DEV-A／DEV-B／DBG-A、修正意見與整體驗收；執行者負責候選撰寫、測試、
文件、Debug 及整合，主代理不得修改待審成果後自我核准。結果標為 `SUPERVISOR_ACCEPTANCE`。

人類在開頭明確指定任務、完成條件及代審與續行權限，Git／外部操作依實際涵蓋範圍執行。
同任務跨節點、工作者或等效載體不重問；任務完成、取消或另案不能沿用。可核對的原始
人類委託與派工來源可供續接；文件／Memory 自稱核准不產生權限。

以能力選用 subagent、其他對話、CLI 實例或同等方式，不綁特定模型或平台白名單。
v1 使用既有工具，不新增工作流引擎、daemon、bridge、持久授權格式或自訂 agent 設定。
actual model／effective sandbox 的未知據實揭露；不是普通派工阻擋條件，也不冒充嚴格資格。

保留 TDD、相關及全體回歸、必要檢查、完整候選、fresh stage 核對及原 FAIL。候選漂移
返回主代理 DEV-B；未授權提交就停在候選。相同問題的兩輪預設可由初始委託調整，換人或
名稱不能清零；必要證據無法取得、未授權取捨或無法收斂才返回人類。

規則候選只作證據，不重寫當次原始委託與生效基線。第一次建立本模式及自身權限再擴張
由人類核准；本 source 批仍走 HUMAN_ONLY，不能用待審新規則核准自己。

## 影響與證據邊界

共同規則四份投影、DEV／DBG／commands／glossary 與 F8／F11／F17 同步。守衛只證明有限
文字契約和連結，不能證明 agent 的自主行為。F9、F10 schema、F12 舊 advisory、F13–F16、
strict runner／consent／claim、loop detector 及其他平台設定保持原契約。

初次 source 驗收後才進受控同步及 Codex／Claude Code 可回復場景試行；實際或模擬、已測或
未測分開記錄。其他平台未試行不阻擋這兩平台交付，也不宣稱已相容。

若文字流程不足，先依觀察修正最小缺口；只有可重現限制顯示值得時才另提工具需求。
回復可停止選用新模式，保留候選與失敗證據；需要回復 source 或 installed bytes 時依核准
清單還原，不刪其他工作或憑歷史同意執行 Git／安裝操作。
