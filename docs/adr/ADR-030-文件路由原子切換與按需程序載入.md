# ADR-030：文件路由原子切換與按需程序載入

- 現況：文件路由契約由 ADR-034 取代，F17 由 ADR-034 精簡。
- 日期：2026-09-06
- 狀態：交付 B DEV-A 已以 HUMAN_ONLY 核准；本候選待 DEV-B
- 前提：[ADR-029](ADR-029-文件路由契約與交班相容基礎.md) 的 A 已提交 eaba6219。
- 核准範圍：[交付 B DEV-A](../proposal/ToukaDev_Skill_文件分層讀取_交付B_DEV-A.md)

## 問題

入口同時混合規則、程序、教學與歷史，指定文件問答也被要求讀 current／adapter；
只新增摘要或先改模板會留下 producer／consumer 不一致。

## 決策

1. 原子切換三個 Skills、commands、四份共同規則、root／example current 與模板；核心保留必要
   義務、gate、程序觸發，詳細程序分成七份按階段展開，不建立新巨型 mandatory reference。
2. 已知正本直達，未知才查精簡導航；讀完整必要章節並遵守全部適用父子規則。Quick 的最近
   profile 解析與 payload 不變。唯讀問答不啟動初始化／實作，已知需求不反覆確認。
3. 新專案只建立根 HANDOVER.md；現有 legacy 與舊模板保留，root／CURRENT 無效須阻擋，
   多 legacy 候選須明確選擇。Debug 每次唯一 incident-id，原 FAIL 留存，current 只放精確入口。
4. 同輪完整有效內容與相同相關輸入／環境／命令／覆蓋／結果可消除重複讀取或驗證；未知、
   漂移使相關證據失效。TDD、回歸、安全、quick validators 與 fresh gate 保持，沒有持久 cache。
5. Adapter 保留原檔及所有 profile 邊界，只新增選路。HUMAN_ONLY 不讀操作手冊；strict 仍讀
   完整隔離／模型／PF-1／consent／runner／跨 session 契約，native 讀所選完整 profile。
6. F17 只查命名 inventory 與有限連結／ATX grammar，F2 涵蓋搬移程序引用；F8–F12 的操作
   義務不因搬移失去 coverage，核心 consent markers 留在原位。F13–F16 runtime／AST corpus 不變。

## 驗證與限制

獨立 expected obligations、mutation／safe-control、temporary roots 與三個事前固定場景比較，
結果見 [交付 B evidence](../evidence/document-routing-delivery-b.md)。Framework 根工具鏈依 ADR-015。
機器檢查是封閉 corpus 的靜態證據，不證明任意 Markdown、自然語言、實際模型 context／token、
runtime sandbox 或資料真實性；metadata 檢查保持 best-effort TOCTOU 邊界。

## 交付與回復

B 完整候選通過本次 DEV-B、另取得 stage／commit 授權後才提交。Installed Skill sync、reload／
fresh-session 行為驗證、下游遷移與 push 另行授權，不從 source 成功推定。
需要回復時以 B 完整提交為單位同步還原入口、模板、consumer、guard expectations；legacy 保留。
不改 MkDocs 配置、不發布 raw logs／sealed evidence，也不觸及 examples 業務程式或依賴。
