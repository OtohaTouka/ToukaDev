# ADR-038：第二次改進任務：減法與獨立刪除腳本

- 日期：2026-10-10
- 狀態：已接受（一頁計畫由人類逐條核准，③ 單獨核准；主代理代審）
- 修訂：ADR-034 D1（一頁計畫的內容）、ADR-035 D1（紀錄開頭的更新時間）、D2（網頁功能與總覽排序）與 D4（不寫刪除程式）、
  ADR-036 D3（改進任務的分析、一頁計畫與「不新增腳本」）、ADR-037 D2（刪除程式的位置與執行方式）
- 影響範圍：`dev-workflow/references/progress-record.md`、supervisor-delegation、beginner-guide、
  `improvement-loop/references/improvement-run.md`、`dev-workflow/assets/progress/render_progress.py`、
  新增 `dev-workflow/assets/progress/delete_tmp.py`、守衛 F17 與測試、README、SSOT 導航

## 背景

這是依 ADR-036 進行的第二次改進任務，以減法為主。來源是 ToukaDev 自己的 6 筆待處理紀錄，類型都是白做工：
進度紀錄出錯那筆發生 2 次，其餘各 1 次；人類指定的另一個專案沒有待處理紀錄。人類啟動改進任務，一頁計畫
逐條核准。刪除程式的位置屬於受保護的規則（安全刪法與清理限制），在一頁計畫中單獨列出，由人類單獨核准。

## 紀錄與改動的對應

只寫概括後的教訓。

| 紀錄的教訓 | 次數 | 處理 |
|---|---|---|
| 進度網頁程式遠大於用途，維護成本高 | 1 | D1，已處理 |
| 逐事件手動更新進度紀錄容易出錯：猜時間、路徑的反斜線被弄壞、條列少空格 | 2 | D2，已處理 |
| 「不新增腳本」讓刪除程式只能放進規則文件，每次由 AI 複製執行 | 1 | D3，已處理 |
| 審核只剩 LOW 仍重派 reviewer | 1 | D4，已處理 |
| 一頁計畫太長 | 1 | D5，已處理 |
| 改進迴圈不會主動修剪，行數只報告、不設上限 | 1 | D6，已處理 |

## 決定

1. **D1 進度網頁減肥**：以現有程式為底，保留的功能照搬，其他刪除，並刪掉被刪功能自己的測試；保留功能的測試
   只刪重複，不刪斷言。
   - 保留：HTML 跳脫、紀錄內文不產生連結、CSP 雜湊、不載入外部資源、總覽連結的任務代號條件、只處理
     `.toukadev/progress`、產生器標記與原子寫入、主題存值只接受 light／dark、儲存一律包 try；最上方「需要你決定的事」、
     工作清單／審核紀錄／暫存項目改用依表頭顯示的通用表格（多出的格子不丟、未知狀態值原文照顯示並警告）、
     其他區段與表格外文字原樣顯示、「未清理 N 項」、紀錄最後更新與過期提示、總覽、自動更新與快照提醒、主題切換；
     exit 0／1／2、`configure_streams`、Python 版本檢查與 3.8 語法可解析。
   - 刪除：暫存大小（人類沒有選擇保留）、「需人類決定」標示、細部格式警告與舊格式偵測（只留「紀錄缺少這一區」與
     未知狀態值兩種警告）、「網頁產生於」「總覽產生於」、`<noscript>` 的自動重新整理、`更新時間：` 的解析。
   - 通用表格是新的輸出路徑，所以防注入測試逐區涵蓋工作清單、審核紀錄、暫存項目、已知問題、其他區段與總覽。
   - 捲動位置：以 Edge（`file:`）實測，拿掉自訂還原後，每 5 秒重新整理時瀏覽器自己保留捲動位置，所以自訂還原的程式
     刪除。Safari 仍未驗證。
2. **D2 進度紀錄的更新時機與時間**：
   - 紀錄開頭只剩任務名稱與任務狀態；舊紀錄多一行 `更新時間：` 不影響顯示。總覽改依紀錄檔的修改時間排序。
   - 更新時機：派工、收件或送審（標「審核中」）、審核有結論、需要人類決定、合併、建立或清理暫存。寫進紀錄的時間
     一律取系統時間，直接編輯紀錄文字，不臨時寫程式產生。
   - supervisor-delegation 的事件清單換成「更新時機依 progress-record.md」，只留一份。
   - 更新次數刻意沒減：收件與開始審核合併成一次，人類仍在網頁看得到主代理在審哪部分。處理的是出錯的原因
     （手寫時間、臨時寫程式改紀錄）。
3. **D3 獨立刪除腳本**（受保護規則的修改，人類單獨核准）：
   - 推翻兩個原始決定：ADR-035 D4「不寫自動刪除的程式」（源頭見 ADR-035 背景與 DEV-B 對 `git worktree remove`
     的實測），以及 ADR-037 D2「從標準輸入交給 `python -I -`，不存成檔案」。
   - 仍可接受的理由：ADR-037 之後刪除程式其實已經存在，只是放在文件裡，每次由 AI 複製執行；放進檔案不多出新能力。
     腳本刪之前還會自己再檢查一次，比原本更嚴。「先執行 `check_cleanup.py tmp`、通過才刪、刪不掉就問人類」的流程
     不變，`check_cleanup.py` 仍然只檢查、不刪除；腳本只由 AI 在規則允許時執行，不是自動排程。
   - 新增 `dev-workflow/assets/progress/delete_tmp.py`，在 repo 根以
     `python -I <dev-workflow 安裝根>/assets/progress/delete_tmp.py <路徑> --task <任務代號>` 執行。
     `clear_readonly_then_unlink` 從文件逐字搬過去，條件一條都不改；其餘只加檔頭說明、
     `from __future__ import annotations`、usage、參數解析與路徑自我檢查。
   - 路徑自我檢查：用 `importlib` 從腳本自己的資料夾載入 `check_cleanup.py`（先登記進 `sys.modules`，不改模組搜尋
     路徑），照 `find_repo_root` → `resolve_argument` → `check_tmp` 重跑 tmp 檢查。載入失敗、`CheckError`、任何其他
     例外或檢查不通過時都不呼叫 `shutil.rmtree`，以非 0 結束；`rmtree` 與 `onexc` 綁定同一個通過檢查的路徑。
   - progress-record.md：鎖定那句改指這支腳本；「暫存資料夾的刪法」保留條件清單，加入執行指令與路徑自我檢查；
     刪掉程式碼圍欄、Bash／PowerShell 管線說明與 ASCII 限制（不再經管線，不需要）。
   - 鎖定：F17 舊句換成新句，另鎖執行指令那一行（加嚴）；F2 的資產清單加入這支腳本；3.8 語法測試納入。
   - 測試：改從檔案載入；取消唯讀的每個條件與實際刪除的測試全部保留，實際刪除改在拋棄式 git repo 根執行腳本檔
     （tmp 檢查需要 `.git` 與 `git worktree list`）；新增不刪的測試：錯的路徑、`.toukadev/tmp` 本身、其他任務的資料夾、
     不合法的任務代號、載入失敗（含載入時以 0 結束）、`CheckError` 與其他例外；反向檢查文件沒有不帶 `-I` 執行腳本的寫法。
   - 本機 Windows 實跑：在拋棄式 git repo 根執行候選腳本，刪掉含唯讀 git object 的暫存資料夾；遇到連到外面的硬連結時
     照原錯誤停下，外面那份不變、仍是唯讀；錯的路徑不刪。證據附在 PR 說明。
   - 接受的剩餘風險不變：檢查後到取消唯讀之間，檔案被換成連結的時間差；前提是資料夾只有本任務的 AI 在寫。
     腳本把通過檢查的同一個路徑原樣交給 `rmtree`，檢查後到刪除之間路徑被換掉也屬於這個時間差。
4. **D4 只剩 LOW 不重派**：supervisor-delegation 在寫審分離那句之後加一句：只剩 LOW 時執行者的修正由主代理驗收，
   主代理自己的內容可附理由不修並在最終回報揭露，要修時交原 reviewer（不可用時交另一位非作者的 reviewer）只審差異；
   沒有未解問題時不另加確認輪。主代理自己的修改仍由另一個 reviewer 看。
5. **D5 一頁計畫變短**：一頁計畫以人類要決定的事為主，每項一兩句，以 40 行內為目標；每一項寫對人類有什麼用、不做會
   怎樣，以及風險與能否撤回、誰來做與資料會不會傳到其他公司、合併後刪哪些分支。審核經過與技術細節人類問才說；對抗式
   複審選項那句不變；計畫與一頁計畫同一輪送審；改進任務另依 improvement-run.md。beginner-guide 同步。
6. **D6 改進迴圈加減法與行數上限**：
   - 分析加第 4 點：另列可以刪除或縮小的規則、程式與功能，不限於有紀錄的，附上證據；受保護的規則照該節處理。
   - 一頁計畫每組一列，加寫對人類有什麼用、不做會怎樣。
   - 實作後整個 repo 的淨增減比預估多出 100 行以上，且預估為增加時超過預估的 1.5 倍（預估為減少或 0 時只看多出
     100 行以上），開 PR 前先停下問人類；範圍估計以最不樂觀的一端比較。
   - 「不新增腳本」改成：需要新程式時寫成獨立的小腳本，不放進規則文件。
   - 不碰人類關卡：減法項目同樣逐條核准。

## 不變的部分

13 個步驟與全部審核點、5 種審核模式、寫的人和審的人分開與授權規則。AI 可自動清理的四種項目、清理前檢查程式
與其他已鎖定的句子都不變。常駐載入的規則（四份 AGENTS 共同區塊與各 SKILL.md）沒有增減。

## 後果

- 修訂 ADR-034 D1：一頁計畫的寫法由「列出各項目」改為以人類要決定的事為主，有長度目標。
- 修訂 ADR-035 D1：紀錄開頭不再有「更新時間」行。修訂 D2：網頁功能刪減如 D1，總覽改依紀錄檔的修改時間排序。
  修訂 D4：第 1 種項目改由固定腳本刪除。
- 修訂 ADR-036 D3：分析加減法、一頁計畫加用處與代價、加行數上限，「不新增腳本」改寫。
- 修訂 ADR-037 D2：刪除程式從文件搬到腳本，不再經標準輸入，ASCII 限制取消；條件與鎖定測試不變。
- ADR-037 的已知限制「沒有網頁程式的瀏覽器仍會自動重新整理」隨 `<noscript>` 刪除而解決。
- 已知限制：
  - 長時間工作中沒有新事件時，過期提示會比以前更常變黃或變紅。
  - 網頁不再顯示暫存大小，只顯示未清理項數。
  - 守衛只證明有限的文字契約，不證明 agent 實際照腳本刪除；Windows 專屬測試在 CI 會跳過，靠本機實跑證據。
  - Safari 的捲動位置仍未驗證。
  - Linux／macOS 上，tmp 檢查認不出 `.toukadev/tmp/<任務代號>` 裡的 bind mount 或 FUSE 掛載，`shutil.rmtree` 會進到
    裡面刪除；Windows 的掛載點是 reparse point，不會跟進去。原本文件裡的程式也一樣，不是這次造成的。要補就要改受保護的
    清理前檢查，需要另外核准。
- 已安裝的 Skills 要重新安裝才會用到新規則，由人類決定是否重新安裝。
