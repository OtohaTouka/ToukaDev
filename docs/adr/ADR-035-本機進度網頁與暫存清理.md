# ADR-035：本機進度網頁與暫存清理

- 日期：2026-10-10
- 狀態：已接受（一頁計畫由人類核准；主代理代審）
- 修訂：ADR-034 D3（工作資料夾位置）、D8（進度紀錄的欄位與格式）

## 背景

ADR-034 讓主代理代審成為預設後，人類只跟主代理討論，卻看不到主代理做到哪裡。人類提出：工作開始前先把預計要做的事
寫成一個網頁，開始後顯示哪個執行者在做哪部分、主代理在審哪部分，完成的打勾，讓人類不用開口問就能掌握流程與進度。

網頁必須在本機：ToukaDev 是通用規則，要盡量跨模型、跨工具。

ADR-034 D8 的進度紀錄只規定最小欄位，沒有固定格式，程式無法可靠地轉成網頁；也沒有審核者、任務狀態與暫存。

暫存方面，人類核准網頁內容照草案，並指出 Codex 會在各處留下大量暫存（一次清理就接近 100 GB），問做完要刪除的規則
是否該寫進流程。

AI 建立的工作資料夾、分支與暫存檔原本沒有登記與清理規則。
計畫審核也指出，「登記過就能刪」不夠安全：登記錯一筆就可能刪到共用分支或重要資料，所以能自動刪的
必須是固定的幾種項目，並限定安全刪法。

完成後審核（DEV-B）時，reviewer 實測 `git worktree remove`（不加 `--force`）會直接刪掉被 git 忽略的內容
（例如 `data/`、`.env`），會順著工作資料夾裡的 junction 刪到外部內容，也會丟掉 detached HEAD 上的 commit。
git 內建指令本身不足以防止誤刪，所以本機的清理改成先用只檢查、不刪除的程式確認，再用 git 內建指令刪。

## 決定

1. **D1 進度紀錄格式正本**：新增 `dev-workflow/references/progress-record.md`。第一行任務名稱，接著更新時間與
   任務狀態（進行中／已結束）；五個必要區段（需要你決定的事、工作清單、審核紀錄、暫存項目、尚未驗證與已知
   問題）與三個固定表頭。狀態值加「審核中」「已完成」；執行者產出的項目只用「已驗收」「已合併」表示完成，
   「已完成」只用於審核、人類決定與主代理自己的非產出步驟。
2. **D2 網頁產生程式**：新增 `dev-workflow/assets/progress/render_progress.py`。
   - Python 3.12 以上、只用標準函式庫；從 dev-workflow 的實際安裝根執行，安裝根依目前環境的 Skill 目錄或
     catalog 解析，與其他 sibling Skill 相同；找不到或跑不起來就告訴人類，`.md` 紀錄照樣可讀。
   - 每份紀錄旁產生同名 `.html`，資料夾內產生總覽 `index.html`；一律先寫暫存檔再原子替換。給單一紀錄
     執行時，也會重產同資料夾的總覽 `index.html`，其他紀錄的網頁不重產。
   - 只處理 `.toukadev/progress` 資料夾或其中的 `.md`，其他位置拒絕（exit 2）。產生的網頁帶產生器標記；遇到
     沒有標記的同名 `.html`（例如舊版程式產生的，或不是本程式產生的檔案）不覆寫（exit 1），由人類決定是否
     刪除，AI 不自行刪除。exit 0 是完成，exit 1 是有網頁沒有產生或沒有覆寫，exit 2 是位置、參數或 Python
     版本不對。
   - 網頁完全自含：內嵌 CSS／JS，Content-Security-Policy 為 `default-src 'none'` 且只允許內嵌樣式與腳本，
     不載入外部資源；紀錄文字一律 HTML 跳脫。只有總覽到任務頁、任務頁回總覽的連結，由任務代號產生；紀錄內文
     不產生連結。每 5 秒自動重新整理並盡量保留捲動位置；淺色／深色。
   - 過期提示：看紀錄檔（`.md`）本身的修改時間，不看網頁產生的時間；網頁顯示
     「紀錄最後更新：HH:MM（N 分鐘前）」。只有任務狀態是「進行中」才提示：
     超過 30 分鐘變黃、超過 120 分鐘變紅；「需要你決定的事」有內容時改顯示「等你決定」，不變色。「已結束」或
     缺少任務狀態時不提示（缺少時另有格式警告）。
   - 依表頭名稱解析：缺欄位、認不得的欄位、缺必要區段與未知狀態值都明顯警告，不悄悄丟掉；舊格式紀錄照樣
     顯示並標「舊格式」。審核紀錄依原本順序顯示。
   - ✔ 只出現在已驗收、已合併；已完成顯示中性「完成」。暫存項目以固定條件標「需人類決定」，只是提示。
   - 暫存大小只算 repo 內可安全走訪的位置：排除 repo 根、`.git`、`data/`、含 `..` 的寫法與 Windows 磁碟相對路徑；
     起點不得是連結，不追蹤 symlink／junction；整次合計上限 20 萬個檔案或 2 秒，超過就標示未完整計算。
   - 總覽每個任務一列（名稱、任務狀態、紀錄最後更新、待決事項數、進度、未清暫存數與大小），依紀錄內寫的更新時間由新到舊；
     任務代號 `index` 保留給總覽。
3. **D3 進度紀錄規則**：supervisor-delegation 的「進度紀錄」改為指向 progress-record.md，並加入五句必要句。
   人類核准計畫時，主代理把全部工作項目列成待辦；每次更新後執行產生程式；啟動時告訴人類紀錄與
   `index.html` 的完整路徑（macOS 上 `.toukadev` 預設隱藏）。進度紀錄仍是工作檢視，不是 current，也不是授權。
4. **D4 暫存清理**：
   - 暫存檔放 `.toukadev/tmp/<任務代號>/`，任務代號只用小寫英數與 `-`、不得為 `index`，新任務代號也不得與
     `.toukadev/progress/` 或 `.toukadev/tmp/` 裡已有的名稱重複；工作資料夾放
     `.toukadev/worktrees/<任務代號>-<單位>/` 或工具自己管理的位置，不放在 `.toukadev/tmp/` 底下。
     建立就登記到「暫存項目」；派工範本加「暫存位置」欄。審核協議 §6.1 的暫時 index 依其規定放在 git 目錄或
     系統暫存資料夾，用完即刪，不受這些限制。
   - 新增清理前檢查程式 `dev-workflow/assets/progress/check_cleanup.py`：只檢查、不刪除，在 repo 根執行（在工作
     資料夾裡執行會被拒絕）；全部條件符合時印「可以清理」並 exit 0，不通過時列出原因並 exit 1，參數錯誤或
     Python 版本太舊時 exit 2。本機的三種項目刪除前都要先通過；只有 exit 0 才刪，其他一律問人類。
   - AI 可自動清理的只有四種，各有限定刪法：本任務建立並登記的 `.toukadev/tmp/<本任務代號>/` 這一層（先過
     `check_cleanup.py tmp`，裡面不得有 git worktree，用不跟著連結走的刪法）；本任務的 AI 自己用
     `git worktree add` 建立並登記的工作資料夾（先過 `check_cleanup.py worktree`：本 repo 在 `.toukadev/worktrees/`
     下、HEAD 在指定分支、沒有改動或未追蹤檔、被忽略的只有可重建的快取、連結只允許可重建快取裡面的 POSIX symlink；通過才用
     `git worktree remove`，不加 `--force`；工具自己建立或管理的不刪）；本任務建立並登記的本機分支（先過
     `check_cleanup.py branch`，再 `git branch -d`，不刪目前所在分支）；本任務建立、推上去並登記的遠端分支
     （以它為 head 的 PR 已合併，用 `git ls-remote` 讀到的遠端 commit 等於 PR 的 `headRefOid`，且在核准的 Git
     範圍內；用 `git push --force-with-lease=refs/heads/<分支>:<headRefOid> <遠端> --delete <分支>` 比對後才刪）。
     預設分支與共用分支永遠不刪。
   - 其他項目、條件不確定、檢查不通過或指令失敗時問人類，不強制。結束時每項「已清理」或「保留」（附理由），清完才算
     完成；要保留的證據先寫進回報。工具自己的快取只提醒位置與大小。原四模式沒有進度紀錄時列在最終回報。
   - 不寫自動刪除的程式；檢查程式只檢查，刪除一律由 AI 在檢查通過後用 git 內建指令或刪除限定資料夾執行。
5. **D5 共同基線**：四份 `AGENTS.md` 共同區塊「文件協議」末尾新增一行登記與清理規則（人類核准計畫即同意）。
6. **D6 守衛與 CI**：F2 檢查清單加入 progress-record.md 並認得 `assets/progress/` 引用；F17 鎖定 SKILL 觸發行、
   五句必要句與共同基線新行；守衛掃描時排除 `.toukadev/`；CI 的 ruff 範圍加入 `dev-workflow`；新增產生程式
   與清理前檢查程式的測試，並測試 progress-record.md 的表頭與程式內的表頭一致。
7. **D7 本任務照新規則跑**：本任務的進度紀錄依新格式補齊全部項目，網頁完成後用它看本任務。

## 不變的部分

13 個步驟與全部審核點、5 種審核模式與授權規則。進度紀錄與網頁都不是授權。

## 後果

- 修訂 ADR-034 D8 的進度紀錄欄位與格式：工作清單的「審核」欄改為「審核者」並加「備註」；審核紀錄的
  「審核者」拆成「寫的人」「審的人」；新增「任務狀態」行與「暫存項目」區段，以及「審核中」「已完成」兩個
  狀態值。舊格式紀錄仍會顯示並標「舊格式」。
- 收斂 ADR-034 D3 的工作資料夾位置：由「repo 外或 git 忽略的位置」改為 `.toukadev/worktrees/` 或工具自己
  管理的位置；清理前檢查程式只接受 `.toukadev/worktrees/` 下的工作資料夾。
- Linux／macOS 的例外：`.venv` 等可重建快取裡本來就有 POSIX symlink，所以快取裡面的 POSIX symlink 允許通過；
  快取以外的 symlink、快取資料夾本身是連結，以及任何 Windows junction 或 reparse point（含 Windows 上的 symlink）
  都不通過。這個例外的實證方式是 CI 在 ubuntu 上實際執行一次刪除，並確認連結指向的外部檔案完好。
- 舊版產生的網頁沒有產生器標記，新版不會覆寫，要人類決定是否刪除。
- 共同基線多一行；新專案範本與 examples 同步。
- 已知限制：
  - 過期提示分不出長時間工作與忘了更新；人類要確定時仍要問主代理。
  - 網頁的「需人類決定」標示只是提示；沒有標示不代表可以刪，能不能刪以 progress-record.md 的規則為準。
  - Safari 的捲動位置保留未驗證。
- 守衛只證明有限的文字契約，不證明 agent 實際依規則登記與清理。
- 已安裝的 Skills（例如 `~/.codex/skills`）要重新安裝才會用到新規則，不在本次核准內。
- 13 步驟程序精簡（第二批）不在本 ADR 範圍。
