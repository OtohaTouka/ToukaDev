# ADR-019：新手審核漸進揭露與使用者可見名詞契約

- **現況：** 技術收據由 ADR-034 移除。
- **日期：** 2026-08-18
- **狀態：** 已接受
- **影響範圍：** DEV-A／DEV-B 呈現、HUMAN_ONLY 說明、glossary、Skills、Commands、templates、examples、F11
- **延續：** ADR-003 審核模式與風險、ADR-004 資料條件揭露、ADR-011 文件快速路徑

## 問題

ToukaDev 已有完整的 reviewer、資料條件、候選 seal 與授權契約，但審核輸出把摘要、hash、manifest
與 assurance evidence 平鋪在同一層。新手很難辨識「現在只要決定什麼」，熟練使用者也容易漏看
傳輸範圍、成本未知或重大風險。此外，「精簡模式」、「輕量路徑」、「輕量流程」分別曾指向
輸出詳略、純文件變更與初始化規模，名稱相近但安全邊界不同。

若只縮短輸出而沒有明確契約，可能把重要風險藏入折疊內容；若直接改掉 `/quick` 或
`模式：精簡`，又會破壞現有專案與 command 的相容性。

## 決策

1. `dev-workflow/references/review-protocol.md` 是審核呈現契約的唯一正本。DEV-A／DEV-B 先顯示
   使用者可見摘要，固定包含目前決定、風險、傳輸內容、費用不確定性、推薦選項與一行核准方式。
2. 完整 hashes、candidate manifest、patch digest、assurance evidence 與 data conditions 放入
   `<details>` technical receipt。折疊只降低初始資訊密度，不降低可驗證性。
3. `HIGH`、`BLOCKING`、重大安全與不可逆風險必須同時留在可見摘要；technical receipt 不能成為
   隱藏重大風險的地方。
4. `HUMAN_ONLY` 必須顯示「只有人類審核；未完成獨立 AI 技術驗證」，不得把人類確認包裝成
   獨立 reviewer 結論。
5. 使用者可見名稱統一為「精簡輸出模式」、「文件快速路徑」與「小型專案初始化」。既有
   `模式：精簡` 與 `/quick` 保留為 machine token／入口；舊顯示名稱只在 glossary 相容映射中保留。
6. 推薦選項只是建議，不代表同意資料傳輸、啟動 reviewer、commit、部署或任何不可逆操作；
   這些 gate 仍逐次取得精確授權。
7. `scripts/guard_framework.py` 新增獨立 F11。F8 繼續治理 reviewer 資格與通過條件，F11 只驗證
   progressive disclosure、技術收據、HUMAN_ONLY 說明、術語映射與必要使用端。
8. 本批不修改 reviewer runner、consent、claim、ADVERSARIAL 執行、資料傳輸或 production 能力。

## 理由

- 短摘要讓使用者先處理真正的決策；technical receipt 仍保留完整可重現證據。
- 將重大風險固定在可見層，避免 progressive disclosure 退化為風險隱藏。
- 名詞依不同責任命名，可區分「輸出變短」、「變更流程縮短」與「初始化規模縮小」。
- 保留 machine token，能在不破壞既有設定與 command 的前提下改善顯示名稱。
- F11 與 F8 分責，可防止新手 UX 改動意外改寫正式 reviewer 安全契約。

## 未採用方案

### 只更新 README，不新增守衛

拒絕。跨 Skill、Commands、templates 與 examples 的名稱很容易再次漂移，且無法證明重大風險仍在
可見摘要。

### 把所有技術證據永久展開

拒絕。雖然完整，但無法解決新手不知道當下決策的問題；可展開收據能同時保留清晰與可驗證性。

### 直接刪除舊 token

拒絕。現有專案的 `AGENTS.md` 與 `/quick` 入口可能仍使用它們；顯示名稱更新不應造成破壞性遷移。

## 代價與殘餘限制

- Markdown client 對 `<details>` 的呈現可能不同；不支援折疊時內容會展開，但仍可讀。
- F11 驗證必要文字與使用端，不能證明每個模型每次都產生完美摘要；DEV-B 仍須審核實際輸出。
- 舊名稱可能存在歷史 ADR／handover 或相容說明中；它們不是新的使用者可見正本。
- repo commit 不會同步 installed Skills；部署與新 session reload 留給獨立的受控同步 gate。

## 回復方式

若此契約造成誤導，必須一起回復 review protocol 的 UX 區塊、F11 與測試、glossary 相容映射、
全部 consumer 名稱、SSOT、ADR-019／index、roadmap 與 handover。不得只移除重大風險可見規則或
HUMAN_ONLY 誠實標示。
