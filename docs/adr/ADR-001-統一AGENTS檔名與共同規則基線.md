# ADR-001：統一 AGENTS.md 檔名與共同規則基線

- **日期：** 2026-07-23
- **狀態：** 已接受

## 問題

ToukaDev 原先用 `AGENTS.md` 表示框架層規則、用 `Agents.md` 表示專案層規則。這種做法把作用域綁定在檔名大小寫上，在 Windows 上不易察覺差異，到了大小寫敏感的檔案系統或只識別標準名稱的工具時，可能無法載入專案規則。

此外，框架根規則、專案範本與 examples 各自維護相似的工程原則，缺少可自動驗證的共同基線。

## 決策

1. ToukaDev 內所有正式規則檔一律命名為 `AGENTS.md`。
2. 框架層與專案層由檔案所在目錄與作用域區分，不再由大小寫區分。
3. 根目錄 `AGENTS.md` 內的 `toukadev:shared-rules` 區塊是共同工程規則的唯一正本。
4. 專案範本與兩個 examples 必須攜帶完全相同的共同區塊，再於區塊外加入各自的專案設定。
5. `guard_framework.py` 必須同時檢查磁碟與 Git 索引中的精確檔名、共同區塊同步及操作文件中的舊名稱引用。
6. 舊專案只有 `Agents.md` 時走遷移流程；兩種名稱同時存在時停止，不自動合併。

## 理由

- `AGENTS.md` 是可跨多種代理工具共用的明確名稱。
- 位置比大小寫更適合表達規則作用域。
- examples 必須能獨立複製使用，因此不能只引用 ToukaDev 根目錄檔案。
- 以標記區塊加守衛同步，可兼顧獨立可攜性與 SSOT。
- 明確處理舊檔與雙檔衝突，避免工具讀到不同規則。

## 影響

### 正面

- 新專案不再產生混合大小寫檔名。
- Windows 與 Linux 都能由守衛發現命名錯誤。
- 框架、範本與 examples 的共同規則可自動驗證。
- 框架層與專案層的責任邊界更清楚。

### 權衡

- 共同區塊會複製到可獨立使用的範本與 examples，增加少量內容重複。
- 修改共同規則時必須同步四份檔案。
- 舊專案需要一次性的檔名遷移。

## 不在本決策範圍

- 不新增 `CLAUDE.md`、`GEMINI.md` 或其他工具專屬轉接檔。
- 不修改 ToukaDev repo 之外既有專案的檔案。
