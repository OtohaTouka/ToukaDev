# ADR-029：文件路由契約與交班相容基礎

- **現況：** 文件路由契約與 helper 由 ADR-034 取代。
- **日期：** 2026-09-06
- **狀態：** 已接受；A 已提交 eaba6219，consumer 切換見 ADR-030
- **影響範圍：** 文件路由 reference、唯讀 helper、F17、相容性 fixtures
- **核准輸入：** [文件分層讀取更新實作計畫 v2](../proposal/ToukaDev_Skill_文件分層讀取更新實作計劃.md)

## 問題

現行流程要求載入長篇 Skills、規則與日期型交班，文件用途混合且精確入口不足。
直接一次替換新模板會讓舊 consumers 無法接手；只新增分層說明又不能證明契約一致。
使用者要求降低 context 負擔、精準取得資訊，並減少不必要步驟與驗證。

## 決策

1. 分成可獨立全綠的 A／B 交付。A 建立契約與相容基礎；B 才同步切換 Skills、commands、
   四份共同規則、模板、current 入口及必要導航。本 ADR 不授權 B 或 installed Skill 同步。
2. 以 `dev-workflow/references/document-routing.md` 作語義正本，保留唯一、完整的 version 1
   機器投影。已知正本直接讀；未知位置才查導航。所有適用規則及必要契約前提仍須遵守。
3. `scripts/document_routing.py` 提供最小內部函式；不建立一般 CLI、runtime router、
   全 repo discovery、persistent cache、read receipt 或授權系統。
4. Current 選擇優先根 HANDOVER.md，再使用 docs/handover/CURRENT.md。已存在但無效的入口
   阻擋 fallback；CURRENT.md 是文件，不定義機器指標語法或自動追隨連結。
5. Legacy 由 caller 提供完整、已授權的候選與 navigation 分類。單候選可使用；多候選
   只列 metadata 等待明確選擇。不得猜最新、讀全部內容或刪減名單製造唯一候選。
   TEMPLATE.md 排除，README 只有被明確分類為導覽時排除。
6. 路徑只接受精確大小寫的 project-relative regular file；拒絕已觀察到的越界字串、
   symlink／junction／reparse、大小寫衝突、無法讀取、空文件與讀取前後 metadata 漂移。
   這是 best-effort observation，無法消除所有 TOCTOU，也不證明內容真實性或授權。
7. F17 只新增 routing 契約的有限檢查，expected fields 由程式獨立保存，不能從待驗文件
   推導。A 不要求未切換的 consumers 已採新格式；既有 F1–F16 保持原責任。
8. 同一輪結果只在相關輸入、環境、命令及覆蓋相同時才可去除重複驗證；fresh gates 仍重驗。
   這些操作規則須於 B 正式切換後才適用，不能用 A reference 略過目前流程。

## 取捨與界限

- V1 不理解任意自然語言、Markdown URL／anchor 或文件內容是否真正描述 current state。
  caller 必須補足角色與範圍判斷；B 才處理 consumer 連結與程序觸發點。
- 檔名 metadata 的 shallow 列舉用於精確大小寫檢查，不是逐路徑 OS 隔離；不遞迴探索歷史。
- 無已宣告候選只表示本次輸入為空，不表示 repo 不存在其他來源。
- 保留現有交班與受保護 evidence；不做歷史搬移、刪除或下游專案遷移。
- F17／fixtures 通過不等同實際模型載入量、速度或任務品質改善；有限 before／after 留到 B。

## 驗證與回復

以 routing mutation／safe-control、root／CURRENT／legacy、多候選零內容讀取及錯誤路徑 fixtures
建立 Red→Green；交付前執行 root 全體回歸、Ruff 與 framework guard。保留原始 RED 及平台限制，
不以文字 marker 測試宣稱完整模型行為驗證。

若取消 A，在候選審核與精確回復範圍核對後移除新 helper／reference／tests／F17 及其文件連結；
現行 consumers 與模板未切換，因此不需要改寫歷史交班或回復下游專案。本段不是刪除授權。
