# ADR-054：搜尋時暫停進度網頁自動更新

- 日期：2026-11-17
- 狀態：已接受（一頁計畫由人類核准：「甲」；主代理代審，單一寫入者；實作在本 PR）
- 修訂：ADR-037 D4 的暫停提示（原本只有選取文字時暫停）
- 影響範圍：`dev-workflow/assets/progress/render_progress.py`（網頁腳本、暫停提示、樣式、模組說明）；`tests/test_render_progress.py`；
  `dev-workflow/references/` 的 `progress-record.md`、`beginner-guide.md`；ADR 索引、ADR-037 現況行、`HANDOVER.md`

## 背景

進度網頁用一般瀏覽器開啟時每 5 秒重新整理，只在選取文字時暫停（ADR-037 D4）。人類用 Ctrl+F 在總覽裡搜尋時沒有選取，
頁面一重新整理，搜尋就被打斷、跳回原處。

## 決定

1. 在頁面上按 Ctrl+F、Cmd+F 或 F3 時暫停自動更新。只認 Ctrl 或 Cmd 加 F（`event.key` 或 `event.code === "KeyF"`），
   有 Alt（含 AltGr）不算；Shift 不限制。不呼叫 `preventDefault`，瀏覽器自己的搜尋列照常打開。
2. 恢復：網頁先失去焦點（搜尋列拿走焦點）、之後又拿回焦點（搜尋列關掉）；或在頁面上按滑鼠、按 Esc。
   沒有先失去焦點就收到的 focus 不算。恢復後 5 秒內照常重新整理。沒有逾時自動恢復。
3. 暫停提示有兩句，各在自己的 span：選取文字那句照舊，搜尋時改顯示「已暫停自動更新：你在搜尋（關掉搜尋列或點一下頁面就恢復）」。
   腳本用 `notice.dataset.reason` 設定原因（`search`、`select` 或空），CSS 依原因只顯示一句；HTML 不寫死原因。
   這是多一處只寫固定值的屬性；`setAttribute` 仍只有主題一處，`dataset` 也只有這一處（測試鎖住）。
4. 搜尋優先於選取：搜尋中有選取時顯示搜尋那句。
5. 快照（`data:`）、內容安全政策只認雜湊、提示固定位置、重新整理最先排好，這些照舊。

## 後果

- 找到字之後關掉搜尋列，瀏覽器通常會把找到的字變成網頁的選取（Chrome、Edge 一般如此，本次未實測：headless 沒有搜尋列，
  人類實際試 Ctrl+F 時一併確認；Firefox、Safari 推測相同），
  所以提示會換成「你選取了文字」，網頁繼續暫停，點一下頁面才恢復。沒有用程式清掉選取：那會蓋掉使用者剛找到的位置。
- 偵測不到的情況：用瀏覽器選單（不是快捷鍵）打開搜尋列；焦點不在網頁（例如在網址列）時按 Ctrl+F；Firefox 的「/」快速搜尋與
  「打字直接搜尋」。這些照舊會被打斷。
- 有的瀏覽器開關搜尋列不觸發 blur、focus：那時要在頁面上點一下或按 Esc 才恢復，提示寫明怎麼恢復。
- 搜尋中點一下頁面（含拖捲軸，推測）就恢復；搜尋列如果還開著，5 秒內照常重新整理。切分頁回來時焦點可能還給網頁，也會恢復（推測）。
- 有幾種按鍵也會被當成搜尋而暫停，點一下就恢復，不另外排除：Mac 的 Cmd+Ctrl+F（全螢幕）與 Ctrl+F；
  Dvorak 這類配置下 Ctrl 加實體 F 位置的鍵（認 `code === "KeyF"`）；F3 加任何修飾鍵，以及 Mac 的 Fn+F3。

## 驗證

- 測試整段比對按鍵判斷、暫停原因、提示設定、重新整理前的檢查、開始與停止搜尋、四個監聽；並檢查沒有 `preventDefault`、
  開始與停止搜尋的次數（段落外多一處也會紅）、`dataset` 只有一處、腳本與 CSS 的原因字相同、兩句提示的 CSS 規則整份比對、
  提示兩句的文字與 HTML 不寫死原因。
- 改壞驗證：先跑沒改壞的綠基準，再逐項改壞 17 處（Alt、Ctrl 或 Cmd、F3、先 blur 才恢復、搜尋優先、監聽在 window、
  不擋搜尋列、重新整理前看暫停原因、搜尋時藏選取那句、腳本設定原因、Esc、滑鼠、提示有搜尋那句、兩句被無條件藏起來、
  選取改變也停止搜尋、多一處 `dataset`），每一處都讓對應的測試或整段比對變紅。
- 本機以 Playwright 的 Chromium 用 `file:` 開產生的網頁：送 Ctrl+F、F3、Cmd+F、Alt+F 的按鍵，模擬 blur、focus、按滑鼠、Esc、
  選取文字，14 項都符合，且網頁沒有擋掉按鍵的預設動作。headless 沒有真的搜尋列，實際按 Ctrl+F 由人類試。

## 不採用

- 把兩句提示合成一句（例如「你選取了文字或在搜尋」）：可以省掉原因與 CSS，但會改到人類核准的提示文字。
- 搜尋結束時清掉選取：會蓋掉使用者剛找到的位置。
- 拉長重新整理間隔：會讓「畫面還在更新」的提示變慢，也不能保證搜尋不被打斷。
