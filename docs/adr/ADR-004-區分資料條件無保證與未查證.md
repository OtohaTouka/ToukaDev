# ADR-004：區分資料條件無保證與未查證

- **現況：** 資料條件三級與 SHA-256 綁定的同意，由 ADR-033 改成：送到其他 AI 服務前說明送什麼、送去哪、對方有無保證，取得人類明確同意；無法說明對方條件時不得傳送。
- **日期：** 2026-08-09
- **狀態：** 已接受；資料條件新鮮度與授權有效期由 ADR-006 補充
- **影響範圍：** DEV-A／DEV-B 外部 reviewer 知情同意、Codex adapter、單 reviewer manifest、F8／F9 守衛

## 問題

ADR-002 要求資料保留、區域或安全 fallback 條件未知時不得傳送。第二批 DEV-B 預檢實際查核
ChatGPT consumer 帳號與 Codex CLI 後，能確認 training use 帳號設定，卻無法由官方資料取得
固定留存期限、資料區域或安全 fallback 的承諾。

原協議只提供「已知／未知」兩種語意，因而把下列情況混為一談：

1. 沒有做查核，無法判斷本次服務的資料條件；
2. 已查核官方條款與帳號設定，但供應商沒有提供固定承諾。

若兩者都永久阻擋，consumer 服務在供應商誠實保留彈性時幾乎無法成為 reviewer；若都允許人類
接受，又會讓未查證狀態被同意文字繞過。

## 決策

1. 外部資料條件逐項分為 `VERIFIED`、`DISCLOSED_NO_GUARANTEE`、`UNVERIFIED`。
2. `VERIFIED` 必須由當下官方條款、帳號設定或可稽核證據確認具體條件。
3. `DISCLOSED_NO_GUARANTEE` 只用於已完成查核且保存證據，但供應商未提供固定承諾的項目。
   傳輸前必須揭露最保守風險並取得人類對本次精確範圍的明確同意。
4. `UNVERIFIED` 表示未查核、來源不明、證據過期或無法判定涵蓋本次服務；它仍會阻擋傳輸，
   不得用「使用者接受風險」繞過。
5. 單 reviewer manifest 升級為 schema version `2`，固定保存 `training_use`、`retention`、
   `data_region`、`safety_fallback` 的 assurance、白話揭露與證據。
6. 結構化資料條件以 canonical JSON SHA-256 綁定；人類同意原文必須同時明列 provider、
   requested model、review input 名稱、input SHA-256 與 data conditions SHA-256。
7. 這個分級只處理資料條件揭露，不放寬 reviewer 的全新上下文、唯讀、禁止 delegation、
   秘密掃描、模型證據與 verdict 上限。

## 理由

- 「沒有固定承諾」是供應商條款的事實，不等於執行者沒有做查核。
- 最保守揭露讓人類能在資訊有限時做真正的風險決定，同時避免 AI 把未承諾事項說成保證。
- `UNVERIFIED` 維持 fail closed，確保同意只接受已揭露的不確定性，而不是取代必要調查。
- digest 綁定能防止同意之後替換資料條件或審核輸入。

## 影響

- ChatGPT Pro 等 consumer 服務若缺少固定留存或區域承諾，不再因此永久無法審核；但每次仍要
  顯示最保守風險並取得精確同意。
- manifest version 1 不再相容；本 ADR 當時要求 version 2，後續已由 ADR-006 的短效授權與
  candidate 綁定升級為 version 3。
- F8／F9 會防止文件把 `UNVERIFIED` 誤寫成可由人類接受後傳送，並驗證 runner 的結構化契約。
- 本 ADR 不代表 OpenAI、Anthropic 或其他供應商目前提供任何特定留存、區域或 fallback 保證；
  每次啟動仍要查核當下服務、方案與帳號設定。

## 取代與保留

本 ADR 取代 ADR-002 決策 9 與原協議中將「無固定承諾」一律視為「未知且不得傳送」的語意。
ADR-003 的模型證據分級、節制多代理與跨 session 授權邊界繼續有效。
