# ADR-037：第一次改進任務：暫存範圍、唯讀刪法、進度網頁

- 現況：D2（刪除程式的位置）由 ADR-038 修訂；D3（不改清理前檢查）由 ADR-041 推翻。
- 日期：2026-10-10
- 狀態：已接受（一頁計畫由人類逐條核准；主代理代審）
- 修訂：ADR-035 D2（網頁只在 `file:`／`http:`／`https:` 自動重新整理，並加淺色／深色切換）、
  D4（第 1 種項目「本任務的暫存資料夾」的刪法）
- 影響範圍：`dev-workflow/references/progress-record.md`、supervisor-delegation 派工範本、beginner-guide、
  `dev-workflow/assets/progress/render_progress.py`、守衛 F17 與測試

## 背景

這是依 ADR-036 進行的第一次改進任務。來源是 ToukaDev 自己的紀錄，以及人類指定的另一個專案的紀錄；待處理的
5 筆都只發生過 1 次。分析依根因分組，先檢查是否不採用；刪除規則屬於受保護的規則，所以唯讀刪法在一頁計畫中
單獨列出、單獨核准。人類逐條核准了四項，也同意執行方式與 Git 範圍。

## 紀錄與改動的對應

只寫概括後的教訓。

| 紀錄的教訓 | 來源 | 處理 |
|---|---|---|
| 暫存資料夾裡有 AI 建立的測試用 git repo 時，Windows 上規定的刪法因唯讀檔失敗，只好中途問人類 | ToukaDev | D2，已處理 |
| 「暫存檔」的範圍沒定義，派工照字面要求工具快取也放進暫存位置，與 repo 自己的快取設定衝突，執行者只好繞路 | ToukaDev | D1，已處理 |
| 同一個缺口：照規則把測試工具的暫存放進暫存位置，與另一個專案的測試要求衝突，多出測試失敗 | 另一個專案 | D1，已處理 |
| 清理前檢查不認得另一個專案的守衛快取，只好問人類 | 另一個專案 | D3，不採用 |
| 看不出進度網頁有沒有在更新 | ToukaDev | D4，已處理 |

## 決定

1. **D1 暫存檔的範圍**（釐清，不是放寬）：
   - progress-record.md「位置」說明：暫存檔指 AI 自己建立的檔案，例如腳本、log、比對用的副本，以及 AI 用指令
     建立的拋棄式 repo。
   - 工具與測試自己的快取和暫存不算暫存檔，照專案設定或工具預設的位置；不為了避開工作資料夾或放進
     `.toukadev/tmp/` 而改工具設定或命令參數。
   - 工作資料夾裡的這類快取，在清理前檢查認得的可重建快取名單內，就跟著工作資料夾一起清；名單外的照規則問人類。
     系統暫存區裡的由工具自己輪替清除；其他留下的只在收尾時提醒位置與大小。
   - supervisor-delegation 派工範本的「暫存位置」欄與 beginner-guide「暫存怎麼清」同步。
     supervisor-delegation 的鎖定句一字不動。能自動清理的四種項目、清理前檢查與「工具自己的快取不自動刪除」都不變。
2. **D2 暫存資料夾的刪法**（受保護規則的修改，人類單獨核准）：
   - 第 1 種項目改用 progress-record.md「暫存資料夾的刪法」的固定程式：Python 3.12 以上的 `shutil.rmtree`
     加一個 `onexc`，不跟著 symlink／junction 走。下列條件全部成立，才取消該檔的唯讀再刪；否則照原錯誤停下：
     - 只在 Windows；
     - 失敗的是 `os.unlink`，錯誤是 `PermissionError`；
     - 路徑先 `abspath` 再 `normcase`，用 `commonpath` 確認在清理前檢查通過的那個路徑底下；
       不同磁碟時 `commonpath` 丟出的 `ValueError` 要接住，改丟原本的錯誤；
     - `os.lstat` 讀到一般檔案、沒有 reparse point、確實有唯讀屬性；
     - 沒有其他硬連結（`st_nlink` 等於 1）；
     - 處理方式：`os.chmod` 有支援才加 `follow_symlinks=False`，取消唯讀後再 `os.unlink`。
   - 規則用語是「規定刪法包含這一項處理；其餘照下方」。「其他任何項目、任何條件不確定、檢查不通過、或上述指令
     失敗時，不強制、不換更強的刪法，改成問人類」這句不變，程式停下時照它問人類。
   - 程式只寫在 progress-record.md 一份，用唯一的圍欄標記包住。執行時從標準輸入交給 `python -I - <路徑>`，不存成檔案，
     也不放進要刪的資料夾。`-I` 比計畫的 `python - <路徑>` 更嚴：`-` 模式預設會把目前資料夾放進模組搜尋路徑，
     repo 根目錄裡同名的 `.py` 可能取代標準函式庫；`-I` 不加入目前資料夾，也不讀 `PYTHON*` 環境變數。
     程式維持純 ASCII，因為 Windows PowerShell 5.1 經管線送給外部程式時預設用 ASCII 編碼，非 ASCII 字元會變成問號。
   - 硬連結（完成後審核的發現與修正）：Windows 的唯讀屬性跟著檔案本身走，硬連結共用同一份屬性。reviewer 實測
     本機 `git clone` 會用硬連結共用 object 檔（`st_nlink` 為 2），舊版程式刪暫存資料夾時把資料夾外那份 object 檔也
     改成可寫。所以加上「沒有其他硬連結」這個條件，有其他硬連結時照原錯誤停下、問人類；連結數讀不到（0）也一樣停下。
   - 鎖定：
     - 圍欄外描述刪法的那一行加進 F17（加嚴）。
     - F17 鎖不到圍欄裡的程式，所以由 `tests/test_tmp_delete.py` 從文件抽出程式執行，鎖住每個「照原錯誤停下」
       的條件：非 Windows、`os.rmdir` 等其他步驟、非 `PermissionError`、資料夾、reparse point、非唯讀、有其他硬連結
       或連結數讀不到、資料夾外（含名稱開頭相同的旁邊資料夾與根目錄本身）、不同磁碟，以及檔案在檢查時已不存在。
       另有一個測試把程式當主程式執行，確認 `shutil.rmtree` 只收到原本的路徑與綁定該路徑的 `onexc`，
       改傳其他路徑或改用 `ignore_errors` 在 ubuntu 也會被抓到。
     - 另有 Windows 專屬的實刪測試：含唯讀 object 檔的 git repo、junction 指向外部且外部唯讀檔完好、
       硬連結到資料夾外唯讀檔時照原錯誤停下且外面那份仍是唯讀、被其他程式開著的檔案照原錯誤停下。
       這些在 CI（ubuntu）會跳過，所以本機 Windows 實跑證據附在 PR 說明。
   - 接受的剩餘風險：`lstat` 到 `chmod` 之間，檔案被換成連結的時間差（TOCTOU）。前提是這個資料夾只有本任務的 AI 在寫。
   - 曾考慮但不採用：
     - 「計畫時事先核准清理例外」：本身就是受保護規則的修改，而且是在還沒看到實際情況時同意。它也牴觸
       「失敗當下問人類」與「只用規定的安全刪法」。
     - 「清理前檢查先列出唯讀檔」：每次仍要問人類，還要多寫程式。
3. **D3 不改清理前檢查程式**（不採用）：
   - 只發生在另一個專案一次。依改進任務程序，只跟某個專案有關的改進，建議寫進該專案，不改 ToukaDev。
   - 把通用名稱 `.cache` 加進可重建快取名單也不建議。現有名單都屬於特定工具；檢查程式在任何深度都比對這個名稱，
     還會連帶放行 `.cache` 裡的 POSIX symlink 與 `.git` 標記。
   - 建議該專案自行處理（另一個任務，另外核准）：讓守衛把快取放在工作資料夾以外，或在快取資料夾放標準的
     `CACHEDIR.TAG` 標記。該專案修好之前，再發生時照規則問人類，屬於預期。
   - 之後其他專案也發生同樣的事，再評估讓檢查程式認得 `CACHEDIR.TAG`。
4. **D4 進度網頁看得出有沒有在更新**：
   - 實作前的查證：主代理 2026-10-10 查證，Claude 桌面版的內建瀏覽器把本機進度網頁載入成 `data:` 快照，網頁程式
     照樣會執行。所以重新整理永遠是同一份內容；「畫面更新於」若照常跳動，會讓人誤以為還在更新。
   - 畫面更新時間：`<head>` 的腳本在 body 解析前，依唯一一份協定白名單（`file:`、`http:`、`https:`）設定 `<html>`
     的 class，由 CSS 決定顯示哪一段。即時協定時，角落顯示「畫面更新於 HH:MM:SS」；其他協定（例如 `data:`）或
     網頁程式沒有執行時，顯示「此畫面不會自動更新」的提醒。一般瀏覽器重新整理時不會先閃出提醒。
   - 自動重新整理：是否即時只看這個 class。即時協定時，重新整理仍是最先排好的動作；快照時不排，所以快照工具
     不會每 5 秒出現 navigate 錯誤。
   - 暫停提示：因為選取文字而暫停自動更新時，畫面下方固定位置顯示原因，版面不移動。
   - 淺色／深色切換：跟隨系統 → 淺色 → 深色，選擇存在該瀏覽器 localStorage 的 `toukadev-progress-theme`。head 腳本
     只接受 `light`／`dark`，只用 `setAttribute` 套用；每次存取都包 try，localStorage 被擋也不影響自動重新整理。
   - CSP 仍只認雜湊：script-src 是兩段腳本的雜湊，沒有行內事件或行內樣式。既有測試由「1 段腳本、1 個雜湊」改成
     「正好 2 段且內容等於已知腳本、兩段雜湊」，一樣嚴格；變異檢查的 7＋3 處改動都被測試抓到。
   - 實測：同日以 headless Edge 154 實測 `file:`、`data:`、關閉網頁程式、localStorage 被擋四種情況，都符合預期
     （`data:` 下主控台 0 則訊息）。
   - 文件註明某些工具只把本機檔案顯示成快照、不會自動更新；規則本文不寫日期，實測日期只記在本 ADR。

## 不變的部分

13 個步驟與全部審核點、5 種審核模式與授權規則。AI 可自動清理的四種項目、清理前檢查程式
（`check_cleanup.py`）與已鎖定的句子都不變。常駐載入的規則（四份 AGENTS 共同區塊與各 SKILL.md）沒有增減。

## 後果

- 修訂 ADR-035 D4 第 1 種項目的刪法：由「用不跟著連結走的刪法」改為固定程式，包含 Windows 唯讀檔的處理。
- 修訂 ADR-035 D2：網頁由「每 5 秒自動重新整理」改為只在即時協定自動重新整理，快照時顯示提醒；淺色／深色
  除了跟隨系統，也能手動切換。
- Windows 上遇到唯讀檔時，人類不再被問，也就少了一次親眼確認的機會；人類核准時已知道這個代價。
- 已知限制：
  - 守衛只證明有限的文字契約；圍欄裡的程式靠測試鎖住，不證明 agent 實際照程式刪除。
  - Windows 專屬的測試在 CI 會跳過，要靠本機實跑證據。
  - 程式需要 Python 3.12 以上；版本太舊時程式直接停下，照規則問人類。
  - 沒有網頁程式的一般瀏覽器仍會靠 `<noscript>` 自動重新整理，但畫面顯示「不會自動更新」；這是保守的顯示，
    不會讓人誤以為還在更新。
  - 「不閃爍」的證據是 DOM 順序（head 腳本先於 body 設定 class）；headless 瀏覽器拿不到繪製時間，沒有直接量測。
- 已安裝的 Skills 要重新安裝才會用到新規則，由人類決定是否重新安裝。
