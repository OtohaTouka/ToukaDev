## 背景

ADR-034 讓主代理代審成為預設、拿掉多數審核儀式時，把「13 步驟程序精簡」留給第二批，也留下三個 LOW 與三項
已知不一致。本批是那個第二批，方向是減法。

人類指示：Codex 時期加上的部分可以刪改，但不得改變 13 個步驟與審核點，因為它們都是實際出過大錯之後才加上去的。
所以本批只動步驟裡的說明文字、重複的副本與檢查方式，13 個步驟、步驟順序、審核點標題與 5 種審核模式都不動。

查證時看到的情況：

- 步驟 5–9、11、12 的說明累積了命令範例、勾選清單、ERROR／WARNING／INFO 表與命名建議，從第一版就在，
  與專案 AGENTS「技術棧與執行命令」（本來就是命令正本）重複；在 ADR、交班與 PR 中找不到它們擋下錯誤的紀錄。
- SKILL.md 抄了兩份 DEV-A／DEV-B 選單，審核協議 §1.1、§1.2 又各有一份，改一處要同步四處。
- 文件快速路徑的 JSON 宣告（schema、解析規格與守衛 F10）只保護四份檔案的一段 JSON，守衛與測試合計約 1,060 行；
  它要解決的「框架與專案跑不同的檢查」「找不到時不自己換」用一般文字宣告也做得到。
- ADR-034 D5 規定「進共用分支前一律 DEV-B，不論由哪個對話或 agent 產生」，但暫時 index 的寫法是「對 `HEAD` 的
  差異」：同一分支上若已有別的對話 commit 但沒審的內容，`HEAD` 已經包含它們，reviewer 看不到。曾有未經完成後
  審核就進共用分支、事後才找到問題的情況，這個事件在版控內沒有紀錄，依主代理的評估處理。
- 第一批留下的三個 LOW：已知 `CRITICAL` 時該在哪一關提；暫時 index 刪掉後 `git diff --cached` 就跑不了；
  用模擬測過的自動送出算不算防誤發保護。第 3 個在版控內找得到原文，第 1、2 個依主代理轉述。

## 決定

1. **D1 步驟內容縮成原則**：
   - 步驟 5–9、11（`implementation.md`）每步只留一段原則與原有的「必須／不得」；命令範例、勾選清單、
     ERROR／WARNING／INFO 表、命名建議，以及與共同基線重複的去重段刪除。實際命令以專案 AGENTS「技術棧與執行命令」為準。
     「直譯器或依賴啟動失敗不算 RED」「測試意外通過」「brownfield 的既有債務」這些有具體用途的句子保留。
   - 步驟 12（`delivery.md`）只留變更摘要的 6 個欄位、進 DEV-B 前不得仍有 ERROR，以及何時開新對話的 4 個條件與授權說明；
     「Commit message 已準備好」這項刪除（步驟 13 本來就寫 commit message）。
   - 步驟 1–2、4 只去掉與共同基線重複的半句與多餘排版；SKILL 的重複讀取句併成一行；SKILL 裡「Codex 原生 reviewer」
     那句刪除（審核協議與共同基線仍有）。
   - dev-workflow/README 的「需要調整的部分」表刪除（SKILL 與程序已不再寫那些路徑）。
   - 每一條被縮短的「必須／不得」都有去向對照，由 DEV-B 逐條核對。
2. **D2 SKILL 不再複製選單**：SKILL 的 DEV-A、DEV-B 兩段選單與前置句刪除；DEV-A 第 3 步改為「依協議 §1.1 顯示五種模式」，
   DEV-B 第 6 步改為「依協議 §1.2 重新顯示五種模式」。選單文字、顯示時機與 5 種模式都不變，只留審核協議一份正本。
3. **D3 DEV-B 範圍從分叉點算起**（加嚴）：審核協議 §6.1 新增一行，審核範圍從共用分支的分叉點算起，包含同一分支上
   其他對話或 agent 留下、還沒通過 DEV-B 的 commit 與改動，不只審本次對話自己做的部分；工作分支那點補上「差異從分叉點
   算起」。SKILL DEV-B 第 2 步、supervisor-delegation 與 beginner-guide 同步。
4. **D4 暫時 index 刪掉後的審法**：記下 tree 編號與分叉點（`git merge-base <共用分支> HEAD`，共用分支用遠端目前的位置；
   沒有共用分支時用 `HEAD`）後刪除暫時 index；reviewer 用 `git diff <分叉點> <tree 編號>` 審，這個指令不需要暫時 index。
   §6.1 的範例照此改寫。progress-record.md 的「暫時 index 用完即刪」不變。
5. **D5 `CRITICAL` 的提出時機**：計畫時已判定為 `CRITICAL`，主代理代審在一頁計畫中把對抗式複審列為強烈建議的單獨選項，
   原四模式在 DEV-A 提出；之後才升為 `CRITICAL`，在升級的那一關提出。§2.1 與 §4 的「當關單獨提出」改成只指計畫核准後
   才升級的情況。人類單獨選擇才算同意的規定不變。
6. **D6 第 9 條的模擬測試**（人類核准部分採計）：防誤發保護若用模擬測試證明，要測到保護本身，例如不該送的時候不會送；
   只測正常送出的不算。這保留第 9 條原本的收窄（不讓聊天機器人每個任務都命中），也不讓只測正常路徑的模擬冒充保護。
7. **D7 初始化驗收記 git 編號**：supervised-initialization 的收件改以 git 編號記下驗收對象（已有 Git 時依 dev-workflow
   審核協議 §6.1；還沒有 Git 時在本任務暫存資料夾 `.toukadev/tmp/<任務代號>/` 建一個暫時 git 目錄，以專案為工作目錄算出
   tree 編號，不在專案裡 `git init`），取代檔案 SHA-256 清單與完整檔案快照；收件仍包括完整檔案清單與內容、可核對的差異。
   scaffold-validation 的步驟 13 依路線分開：選用初始化主代理時，commit 前以 `git write-tree` 比對驗收時記下的 tree 編號，
   提交後核對 `HEAD^{tree}`；其他路線維持只用核准清單、staged 路徑、狀態、內容與差異都和完整候選相符的核對。
   同內容才提交的保證不變。
8. **D8 debug-escalation 的說法**：改成「主代理代審（預設）時由主代理派新的分析上下文並代審 DBG-A；人類改選其他模式時由
   人類換高階模型並審核」，SKILL description、README、root-cause-recovery 與根 README 同步。「主代理不代寫根因」的特例
   保留；SKILL 中「主代理代審只在有效委託內接續」那句鎖定句不改；初始化事故仍只在選用初始化主代理時代審。
9. **D9 文件快速路徑改用 AGENTS 文字宣告**（推翻 ADR-034「不變的部分」中的 validation profile，人類單獨決定）：
   - 四份 `AGENTS.md` 保留「Quick validation profile」標題（共同區塊用「quick profile／quick validators」稱呼它，
     共同基線不必改），內容改成一般命令清單：根 1 行 `uv run --locked python scripts/guard_framework.py`；範本與兩個
     examples 3 行 `uv run python scripts/guard_all.py`、`uv run python scripts/guard_security.py`、有 `mkdocs.yml` 時
     `uv run mkdocs build`，下面再一行：宣告缺少或其中的檔案不存在時，必須停止並改走完整 dev-workflow，不得自行替換命令。
   - SKILL：適用前提通過後、開始 L2 前，找出最近作用域 `AGENTS.md` 的宣告（用任務開始時的版本）；沒有宣告、宣告的檔案
     不存在，或命令含管線、重新導向或多個指令串接時，在 L2 前停止並改回完整步驟 3，不得自行替換。舊專案以 JSON 寫的宣告
     照樣讀取其中命令。
   - 刪除 `quick-validation-profile.md`；其他使用端改指 AGENTS 宣告。
   - 守衛 F10 整段刪除，編號保留不重用（與 F9、F12–F16 相同）；改由 F17 整行鎖定四份範本的命令行、三份專案範本的
     停止句，以及 SKILL 的停止句。
     F11 不再要求已刪的檔案。implementation.md 的品質分層鎖定句改為「docs 仍只在有 `mkdocs.yml` 時執行」。

## 不變的部分

13 個步驟與步驟順序、全部審核點標題（F17 照常檢查）、5 種審核模式與選單文字、選單只在人類要求改選或平台無法派工時顯示、
寫的人和審的人分開、逐次同意與授權規則、DEV-B 綁定完整候選。D3 是加嚴；D4 綁定的仍是同一份內容；D5 只釐清提出時機，
同意方式不變。文件快速路徑本身與它的 DEV-B 不變。

## 後果

- 修訂 ADR-034 D4：暫時 index 刪掉後，以分叉點與 tree 編號審核。修訂 D9：已知 `CRITICAL` 的提出時機、第 9 條的模擬測試措辭。
- 推翻 ADR-034「不變的部分」中的 validation profile；ADR-011 由本 ADR 取代。
- ADR-034 後果中的三項已知不一致：project-init 的 SHA-256 用語由 D7 處理；debug-escalation 的舊說法由 D8 處理；
  「主代理不代寫根因」維持為特例。
- 修訂 ADR-032：品質分層鎖定句的 docs 條件改寫，「不得省略已宣告的 ssot、security validators」不變。
- 已知限制：
  - 下游專案自己的 AGENTS 宣告不受機器檢查（以前 F10 也只檢查本 repo 的四份）；argv、路徑與必要檔案的機器檢查
    改成文字規則（用任務開始時的版本、含管線或串接就停）。
  - F10 原本會擋 `commands/quick.md` 與 SKILL 寫死 L3 命令；退役後改由文字規則（command 只是入口，不另列命令）與審核
    把關，不再有機器檢查。quick.md 這項是已知的取捨，人類核准時已被告知；SKILL 這項在複審時補記。
  - 四份 AGENTS 的命令行只檢查每行剛好出現一次，不檢查順序、多出來的行，也不檢查它們在哪一段、標題是否還在；
    F10 原本要求與標準定義完全相同。「改由 F17 整行鎖定」的保護程度低於 F10。
  - 舊規格明文禁止的反引號、命令替換 `$(…)`，以及遇到 symlink／junction 就停（no-follow），沒有寫進新的文字停止清單；
    新清單只寫管線、重新導向與多個指令串接。
  - 暫時 index 算出的 tree 物件沒有被任何 ref 指到；DEV-B 拖太久時可能被 `git gc` 清掉，`git diff <分叉點> <tree 編號>`
    會失敗，這時要重新計算 tree 編號再審。
  - 分叉點在沒有遠端共用分支的新 repo 退回 `HEAD`，等於原寫法；這種情況沒有其他對話的未審 commit 可漏。
  - 暫時 git 目錄算出的 tree 編號要在同一台電腦、同一工作目錄與同一 `.gitattributes` 下比對。本批在 Windows
    （`core.autocrlf=true`）實跑兩個變體（專案內有 `.gitattributes`，以及沒有、只靠全域換行設定），候選含 CRLF 文字檔
    與二進位檔：暫時 git 目錄與正式 `git init` 後 stage 同樣路徑算出的 tree 編號都相同，暫時 git 目錄也沒有在專案裡
    留下 `.git`。複審後再把暫時 git 目錄放在規則寫的位置（專案裡的 `.toukadev/tmp/<任務代號>/`）補跑兩個變體
