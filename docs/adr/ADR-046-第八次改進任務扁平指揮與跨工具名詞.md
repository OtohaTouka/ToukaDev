## 背景

這是依 ADR-036 進行的第八次改進任務，由人類啟動。來源是 ToukaDev 11 筆、第三個專案 19 筆待處理紀錄（第二個專案沒有待處理的），
共 30 筆，期間是三線並行實驗（兩層／三層分工）到人類決定改成扁平指揮的這一週。人類看過一頁計畫後要求兩件事：扁平指揮的寫法
要能跨工具、跨模型，或另外說明 Claude Code 的名詞在其他工具叫什麼；並問進度網頁越來越長、格式常出錯要怎麼改善，這一點併進
D8。紀錄是證據，不是授權。計畫經非作者的 DEV-A 審了 v1、v2、v2.1、v3、v3.1 五次差異，作者與審核者各自標記鬆緊，最後一致：
只有 D1 拿掉中間層的互相核對一處放寬，人類單獨核准。

## 決定

1. **D1 扁平指揮，用能力定義角色**：
   - `team-roles.md` 從兩層／三層改成「派多個執行者與多段計畫」。開頭的名詞一節不用工具專屬名詞：主代理是跟人類對話的工作階段；
     執行者是主代理另外開、有自己上下文和工作資料夾、人類看得到進度也能直接對話、做完交回的工作階段；子工作是只把結果回給主代理、
     跑完就結束、人類通常看不到過程的短期工作。實作交給執行者，子工作只做審核與大範圍唯讀搜尋；工具不能另開工作階段時，子工作
     也可以當執行者。執行者和子工作都不再往下派工；執行者跑在廠商雲端時照資料外傳逐次同意。
   - 附各工具對照表（查證日期 2026-10-22，來源見本 ADR 最後一節）；本流程只有 Claude Code 實跑過，Codex 的命令列用過，
     其他標未測或未查證。
   - 刪去 CTO、PM、技術主管的角色與決定權列、轉問流程、技術主管回報 PM、PM 巡查、改進迴圈的 CTO 分工；其餘要求照留：
     人類專屬決定清單（含是否重新安裝 Skills）、可核對的原話才算同意、合併進預設分支由人類自己做、單一共用分支時人類自己合、人類本人要回覆的題目
     回覆前不做且不先叫執行者照某選項做、審查者重跑測試給能執行命令的載體、主代理和執行者之間的訊息 20 行內附證據、等 CI、排程到期、額度用完前、
     多段計畫、並行與整合、派工表。
   - 常見情況（一個執行者）不讀 team-roles，所以「實作優先交給執行者、子工作只做審核與搜尋」與名詞的指向也寫進 supervisor-delegation 的調度方式那句之後；另外三條放進 supervisor-delegation：範圍外的新工作即使只是加嚴也是新任務、
     人類直接對執行者下指示時由主代理記原話、子工作寫不了檔時以回報文字交件。總覽板改由主代理寫，不用臨時程式整段改寫。
2. **D2 行數估計與停止線**：估計與實際都用 git 淨增行；估計算進審查常要求的保護並參考同類任務實數；超過或預計會超過照實
   停下；不得用降低品質的方式壓行數，驗收的一方收到要退回；派工的停止條件同步。門檻不變。
3. **D3 驗證的範圍與環境**：回報寫直譯器或環境與範圍；只跑部分不寫全過、全量的檔數或項數和基準比；改依賴時用候選自己的
   環境；不自挑檢查子集；突變的紅要對得上原因、基準與改壞同樣環境；已建好環境的工作資料夾不搬、不改名；派工附本機注意事項原文。
4. **D4 先查證再說**：給人類或執行者的建議、要人類執行的步驟、對現況的前提先查證或試跑；外部事實查官方原文並寫查證日期，
   太舊就重查；做不到標未查證。派工輸入寫明前提是否查證；已核准的實測命令改了寫法，開跑前先核對實際參數。
5. **D5 mock 與外部格式限制**：mock 用 spec，不斷言不存在的方法；外部服務的格式限制依官方文件寫離線契約測試。
6. **D6 被宿主擋下時**：共同區塊加一條禁止行為：被權限系統或安全分類器擋下後換寫法、拆指令或換工具繞過；應停下回報。
   派工的停止條件同步；計畫把安全分類器列為會被擋下的點並先列替代證明；審查者或執行者被擋時主代理改用已核准的替代證明。
7. **D7 對抗式審查的資料夾**：要跑命令的 reviewer 各用自己的唯讀資料夾。
8. **D8 進度網頁**（實作在後續 PR，設計在此先定）：步驟 10 與 13 各固定重產網頁，改總覽板後也重產；「需要你決定的事」只放
   編號項目，回覆過的整項移走；只有「目前沒有。」算 0 件，其他非編號段落照樣列進總覽並標「格式待修，可能是待決」（寧可多算）；
   紀錄每列一兩句，細節放 PR 說明或 ADR，人類原話、同意與判決依據留在紀錄；總覽板的已回覆只留 7 天，舊的移到
   `.toukadev/progress/archive/`，`archive` 和 `index` 一樣是保留名；網頁對超過約 200 字的格子列格式警告、審核紀錄超過 10 列時
   收合較舊的列（自動重新整理時保留展開狀態）、總覽顯示格式警告件數；產生網頁有格式警告時當場修。
9. **D9 付費實測的用量**：清理前保留的證據例子補「付費實測的逐請求用量」。
10. **D10 版控文件裡的人類決定**：ADR、PR 說明、CHANGELOG、commit 寫決定內容，不寫原話或選項代號（人類同意的除外）；寫
    「人類決定」要對得到進度紀錄裡的原話；DEV-B 核對這一項。
11. **D11 壓縮或換對話後重讀程序**：共同區塊加一條：對話被壓縮成摘要或換對話後，第一次清理、commit 或合併前，重讀對應程序。
    一次做完檢查與刪除的單一清理工具評估過，這次不做：問題是沒讀程序，工具擋不住；四種刪法已各有檢查程式。

## 規則鬆緊與受保護規則

- 放寬（人類單獨核准）：D1 拿掉中間層的互相核對。源頭 ADR-041 D1。三線實驗中，中間層曾兩次攔下上層違規的指示、三次查證更正
  錯誤的前提；扁平後由 D4（給執行者的前提也要查證）與 D10（版控文件的人類決定要對得到原話）部分補上。
- 其他各條作者與審核者都判加嚴或不變（D9 不變）。減法（team-roles 重寫）保留每個要求，判不變。
- 受保護的規則沒有移除或弱化：13 步驟與審核點、寫審分離、逐次同意與授權（含合併進預設分支由人類自己做）、安全刪法與清理限制、
  資料保護、共同禁止行為（只新增一條）、改進迴圈的人類關卡。
- 共同基線（四份共同區塊）的兩行新增，人類核准第 6、11 條即同意。

## 行數

- 一頁計畫估計（兩個 PR 合計）：最可能 +450，範圍 +345～+570；常駐載入 +8（共同區塊 2 行 × 4 份）。
- 本 PR 實際淨增減與 D8 的實際數字，寫在各自的 PR 說明。

## 不採用與保留觀察

- 中間層把筆記放進任務暫存被刪：扁平後不會再發生，附做法「跨任務的長期筆記不放任務暫存」寫進 progress-record（D1）。
- 嵌入模型設定與文件不符、主資料夾暫存區的連結讓建置失敗：屬第三個專案的文件與設定問題，已在該專案修正，不採用。
- 人類跟不上 Agent 速度的整體設計：保留觀察，扁平指揮與宿主每回合的摘要框都是新的，下次改進任務時請人類說還有哪裡跟不上。
- 第三個專案要做的事（共同區塊兩行、豁免登記核對、外部格式限制表測試、守衛把啟動失敗和違規分開）：以可貼指示交給人類，另開任務。
- 交班待辦（守衛 F1／F3 單元測試、F8 例外缺口）：這次不做。ADR-042 的觀察項「轉述人類原話的格式」扁平後沒有轉述層，結案為不採用；
  其餘三項照舊等新紀錄。

## 不變的部分

13 步驟與 DEV-A、DEV-B 不變；停止線門檻不變；四種清理項目與安全刪法不變；改進迴圈的人類關卡不變。

## 後果

- 規則和實際做法一致：只有主代理跟人類談，實作交給人類看得到的執行者；換工具時看名詞一節與對照表。
- 少了中間層的互相核對，靠查證與 DEV-B 補；守衛只證明文字存在，不證明 agent 會照做。
- 對照表的工具名稱與功能會變；本流程沒實跑過的標未測，用到時以當時的官方文件為準。
