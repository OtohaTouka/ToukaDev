# 改進迴圈（記錄流程問題與改進任務）

ToukaDev 的 13 步驟與審核點，都是因為實際出過大錯才加上去的。本 Skill 讓這件事有固定的管道：
平常把流程或規則的問題記下來，累積之後由人類決定何時改、改哪些。

## 兩個職責

- **記錄**：平常工作中，流程或規則出問題時，記成主要專案資料夾的本機紀錄
  （`.toukadev/lessons/`，不進版控），記完繼續原本的工作。
- **改進任務**：只由人類啟動（含在大任務一頁計畫核准完成後跑）。讀累積的紀錄、依根因分組，產生改進 ToukaDev 的一頁白話計畫；
  人類逐條核准後，照一般 dev-workflow 任務執行。

## 與 dev-workflow 的關係

- 記錄可以發生在任何流程（dev-workflow、project-init、debug-escalation、asset-workflow）或一般工作中；
  它不是新的步驟或審核點，不改變 13 步驟、審核點與授權規則。
- 主代理代審時由主代理記錄；執行者與 reviewer 把流程問題寫在回報裡，由主代理判斷。
- 改進任務照常經過 dev-workflow 的 DEV-A、DEV-B 與人類核准的 Git 範圍。
- 需要 dev-workflow 的程序時，依本次環境的 Skill 目錄或 catalog 解析實際安裝根；缺少時回報具體缺口，
  不自行安裝。

## 按需程序

- 記錄或更新流程問題紀錄時，必讀 [程序](references/recording.md)。
- 人類啟動改進任務時，必讀 [程序](references/improvement-run.md)。

紀錄範本見 `assets/templates/lesson.md`；需要新手說明才讀 README.md。
