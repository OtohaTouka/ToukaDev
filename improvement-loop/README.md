# improvement-loop

改進迴圈 Skill：平常把流程或規則出的問題記下來，累積之後由你決定何時改進 ToukaDev。
只用 Markdown 與 git，可由支援讀取 Skill 的 coding agent 使用，不依賴特定工具的指令或 hook。

## 這個 Skill 做什麼

ToukaDev 的 13 步驟與審核點，都是因為實際出過大錯才加上去的。以前這些問題要靠你在對話中發現、
記得、再提出來；這個 Skill 把它變成固定的管道，分成兩個職責：

- **記錄**：工作中流程或規則出問題時，AI 在專案資料夾記一筆紀錄，記完繼續原本的工作。
  記錄不改任何規則，也不需要你同意。
- **改進任務**：由你啟動（例如說「開始改進 ToukaDev」，或在大任務的一頁計畫核准做完後跑改進）。
  AI 讀累積的紀錄，整理成一頁白話計畫，每組問題寫「發生了什麼 → 建議怎麼改，或為什麼不改」；
  你逐條核准後，才照一般 dev-workflow 修改 ToukaDev。

## 什麼會被記下來

只記流程或規則的問題，分三類：

| 類型 | 例子 |
|---|---|
| 重大錯誤 | 照做或沒照做而出大錯或差點出事；規則寫錯、漏寫或寫不清楚；問題漏到合併或交付後，或由你才發現 |
| 反覆困擾 | 你表示流程讓你困擾，或對同一件事第二次糾正（說「又」「每次」「說過了」也算） |
| 白做工 | 某個步驟花了時間、費用或你的注意力卻沒有作用，例如問了不必問的事、重複確認、檢查程式誤判；規則缺漏或誤判迫使你介入或停下工作也算 |

一般程式錯誤被測試或審核正常抓到，代表流程有效，不會記。

## 紀錄放在哪裡

- 每個專案自己的 `.toukadev/lessons/`，一筆一個檔案，只在你的電腦上、不進版控。
- 紀錄不寫密碼、金鑰，也不抄 `data/`、`.env` 的內容。
- 紀錄的格式見 `assets/templates/lesson.md`。

## 什麼時候會提醒你

只有發生下列事件時，AI 才在最終回報加一句「可以啟動改進」：新增了重大錯誤紀錄、某筆紀錄第二次發生、
已處理或不採用的問題又發生，或待處理的紀錄累積到 5 筆以上。沒有新事件不提醒；除了下一段的情況，也不會自己開始改進任務。

大任務（有一頁計畫、走完整流程的任務）的一頁計畫會多問一項「做完要不要跑改進」，附建議；你明確回覆要，
主要任務合併並清理後，AI 就自動開始擬改進方案，這時不另提醒。沒回覆、回「不要」，或主要任務取消、沒合併，
就不跑；只對那個任務有效。

## 不會做的事

- 不會自動修改規則；除了你在大任務的一頁計畫說要跑的，也不會自動開始改進任務。
- 13 步驟、審核點、授權、安全刪法，以及改進迴圈自己的關卡（只由你啟動、逐條核准、紀錄不是授權、
  只有改進任務能結案）這類受保護的規則，預設建議保留；不會只因為「白做工」就拿掉，會先想辦法降低成本。
  真的要拿掉或放寬時，會在一頁計畫中單獨列出、附上當初加這條規則的原因，讓你單獨決定。
  寫的人和審的人會各自標出每條改動是加嚴、不變還是放寬，任一方判放寬就單獨列給你。
- 讀其他專案的紀錄時，只讀它們的 `.toukadev/lessons/`；要讀哪些專案，第一次改進時會先問你。

## 安裝

更新既有安裝前，先刪除已安裝的舊 `improvement-loop` 資料夾再複製；`cp -r`／`Copy-Item`
不會刪除新版已移除的舊檔案。下列以 Claude Code 為例；其他工具複製到各自的 Skill 目錄。

```bash
# macOS / Linux（於框架根目錄執行）
cp -r improvement-loop ~/.claude/skills/
```

```powershell
# Windows（PowerShell），於框架根目錄執行
New-Item -ItemType Directory -Force "$HOME\.claude\skills" | Out-Null
Copy-Item -Recurse -Force improvement-loop "$HOME\.claude\skills\"
```

改進任務改了規則之後，也要重新安裝 Skills 才會生效；什麼時候重新安裝由你決定。

## 與其他 Skill 的關係

```
任何流程（dev-workflow／project-init／debug-escalation／asset-workflow）
          │  流程或規則出問題
          ↓
   .toukadev/lessons/ 記一筆 ──→ 繼續原本的工作
          │  你說「開始改進 ToukaDev」，或大任務合併清理後（一頁計畫中你說要跑）
          ↓
   改進任務：一頁計畫 → 你逐條核准 → 照一般 dev-workflow（DEV-A、DEV-B）修改 ToukaDev
```

詳細程序：記錄見 `references/recording.md`，改進任務見 `references/improvement-run.md`。
